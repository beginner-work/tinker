# Build the tinker social feed

> Version: v0.101
> Generated by the founder-package skill (product spec flow).
> Rebased against shipped code by the build-prompts audit (2026-05).

Build the tinker social feed from this prompt. The founder worked through a
guided interview that distilled the idea into the structure below; this is the
imperative form. **This surface ships today as `src/renderer/founders.js`** —
the prompt has been rebased to match what's live (see "What's shipped" below).

The social feed is an **adjacency tool inside tinker** — the *internal working
ground before you go to the Daily Beginner*, in the founder's words. A founder
**picks one of their pitches** and opts it in to be discoverable; the act of
opting in **auto-publishes that picked pitch**. Then on any later visit they
press one button — **"find my founders"** — and tinker reads that pitch, hands
it to the RAG, and returns a quiet results page of adjacent founders whose
pitches actually intersect theirs.

## What's shipped (audit ground-truth)

The feature is **built** in `src/renderer/founders.js` (entry point
`window.tinkerFounders.refresh()`, wired in `renderer.js`; mounted at
`<section id="founders">`). It has grown past the original single-pitch v1:

- A founder now owns **multiple pitches** (`window.tinkerPitches`,
  `tinker.pitches.v1`), so the opt-in screen carries a **pitch picker** — the
  founder chooses *which* pitch to make discoverable. Opting in auto-publishes
  that pitch.
- Three endpoints back it: `api/feed/discoverable.js` (read/set the
  discoverable flag), `api/feed/published-pitches.js` (the founder's own
  published pitches, by slug), and `api/feed/adjacent.js` (the matches). All
  three sit behind the Stytch JWT and use `claude-haiku-4-5-20251001` for
  embedding/adjacency.
- The results page shows the **picked pitch's title** at the top, the
  **"find my founders"** button, a list of adjacent founders on press, a
  **swap-pitch** control (switch which pitch is discoverable), and a **Hide**
  control (opt back out).

## Anti-patterns — do not repeat

- **Don't build it as a scrolling feed.** This is a tool with a results page, not a timeline. *"Always one button, reads the pitch."* No infinite scroll, no auto-load, no "for you" rail.
- **Don't add likes, hearts, reactions, or follower counts.** Nothing that turns this into a performance.
- **Don't add public comments under pitches.** If you want to reach a founder, you reach them directly — not in front of an audience. (And v1 has no contact mechanism at all — see Constraints.)
- **Don't rank by engagement.** Adjacency is the only sort. No "trending," no "popular."
- **Don't put AI-written pitches in the feed.** Every pitch a user sees was written by an actual founder.
- **Don't make all pitches discoverable by default.** Discoverable is OFF until the founder explicitly opts in. This is the load-bearing v1 surface.
- **Don't design new chrome.** Inherit tinker's existing shell — `styles.css`, `design-tokens.css`, the rainbow-web mark, Fraunces / Plus Jakarta / Inter.

## What you're building, in one paragraph

A new top-level surface in tinker called **"founders"** (or the founder's preferred name — confirm in chat). It contains two states: an **opt-in screen** (the load-bearing v1 surface — discoverable is OFF by default) and a **results page** with one primary action, *"find my founders"*. Pressing the button reads the user's pitch (from `pitches.js`), sends it to a new `/api/feed/adjacent` endpoint backed by the RAG, and renders 3–7 founders whose pitches intersect theirs as paper cards with generous padding. There are no likes, comments, rankings, or contact mechanisms in v1 — the results are list-only: name, one-line pitch summary, link to the founder's pitch page.

## Phase plan

- **Single-phase build.** Target web/PWA only. The same `src/renderer/` code automatically inherits to Electron desktop and Capacitor mobile, but no platform-specific work in v1. Test in a desktop browser via `npx vercel dev` per README.

## Build sequence

1. **Schema + discoverability flag.** Add a `discoverable_at` timestamp (nullable) to whatever row already stores the founder's pitch in `TinkerUserData` (or a sibling row if cleaner). `NULL` = not opted in; non-null = opted in at that moment. No global "discoverable" boolean — the timestamp is the source of truth so we can show "opted in [N] days ago" if useful later.
   **CHECKPOINT — stop and report.** Confirm the column lands on the right table and the existing pitch read/write paths still work. Get founder confirmation before moving on.

2. **Opt-in screen — the v1 hero surface.** Sidebar item ("founders") that routes to a single page. If the user is not opted in, the page is the opt-in screen: the **pitch picker** (choose which pitch to make discoverable), the shipped one-paragraph explanation of what discoverability means, and one primary button **"Make this pitch discoverable"** (opting in auto-publishes the picked pitch). No marketing copy. No "join the network" language. Visible-string allowlist applies (see Constraints).
   **CHECKPOINT — stop and report.** Render the opt-in screen and let the founder click through it before continuing. Confirm the copy reads right.

3. **Adjacency endpoint.** New Vercel function at `api/feed/adjacent.js`. Takes the JWT, reads the user's pitch from the existing pitch table, embeds it via the same Claude path used for tinker search (`api/search.js` is the reference), and returns 3–7 adjacent founder pitches from the corpus of opted-in users. The selection rule is the RAG's similarity over pitch text — no engagement signal, no recency boost. If fewer than 3 opted-in founders exist whose pitches return above the similarity threshold, the endpoint returns whatever it has (including zero results) with a flag `coldStart: true`.

4. **Results page.** If the user is opted in, the page shows their pitch summary at the top, then the **"find my founders"** button. Pressing it calls `/api/feed/adjacent` and renders the response as a vertical list of paper cards — one per founder — with **generous padding around each card** (the quiet-home mood cue). Each card shows: founder name, one-line pitch summary, and a link to the founder's full pitch page (the existing pitch UI, viewed in read-only mode for a non-owner). No likes button, no comment box, no reach-out button, no rank number.

5. **Empty / cold-start state.** When the endpoint returns `coldStart: true` with zero or 1–2 results, the results page renders an honest empty state: the verbatim line *"You're early — there aren't enough founders here yet for a match. Check back as more opt in."* (or the founder's preferred phrasing; confirm in chat). No fake placeholder cards, no synthetic founders.

6. **Hide / opt out.** A small secondary control on the results page: **"Hide my pitch from other founders."** Clicking it nulls the `discoverable_at` timestamp; on next load the page falls back to the opt-in screen.

## Constraints (non-negotiable)

- **No likes, hearts, reactions, or follower counts.** Anywhere.
- **No public comments.** No reply UI under pitches. No DM UI in v1 either (see "list-only" below).
- **No engagement-ranked feed.** Adjacency is the only sort.
- **No AI-written content in the feed.** Every pitch shown was written by an actual founder.
- **Tool with a results page, NOT a scrolling feed.** One button, one results page. No infinite scroll.
- **List-only v1.** Results page shows name + one-line pitch summary + link to the founder's pitch page. No contact mechanism, no DM, no reveal-email button. Confirmed in narrowing.
- **Discoverable is OFF by default.** Opt-in is explicit and reversible.
- **Inside tinker chrome.** Inherit `src/renderer/styles.css`, `design-tokens.css`, the rainbow-web mark. Sibling screen, not a new design.
- **Quiet home mood.** Generous padding around each pitch card — the page breathes; rows aren't packed tight. No animated transitions. No decoration beyond the existing tinker chrome.
- **Visible-string allowlist.** Every visible string on the rendered page must be one of:
  - (a) a verbatim quote from the founder's transcript / input, OR
  - (b) a fixed UI string from the allowlist below.

  Anything outside (a) or (b) is a bug. Before v1 is considered done, walk every text node on the rendered page; verify each is either in the founder's transcript or in the allowlist. The check is a build step.

## Open questions — ask the founder, don't invent

- **What's the sidebar item called?** Draft is `founders`. Confirm or replace.
- **What does the opt-in paragraph say?** The screen needs one paragraph explaining what "discoverable" means in the founder's own words. Don't invent it. Ask.
- **How does this opt-in interact with the existing pitch publication flow to Daily Beginner?** Same opt-in toggle, or separate? The founder said this feed is *"the internal working ground before you go to the Daily Beginner"* — implying tinker discoverability is a private peer layer and Daily Beginner is a separate public step. Confirm.
- **What does "adjacent" mean concretely in the RAG?** Top 3–7 by similarity? A similarity threshold? If the threshold returns 12, do we cap at 7 or show all?
- **Does the results page route to the founder's pitch page in tinker, or to a public profile on beginner.work?** Today the pitch UI in tinker is private. If the link is to a read-only view of someone else's pitch, that view doesn't exist yet — flagging.
- **What's the empty-state line, in the founder's own words?** Draft is in the allowlist. Replace before ship.

If you must move forward without an answer, mark `[NEEDS INPUT]` in a code comment and pick a sensible default.

## Done when

- A founder can land on the **founders** screen, see the opt-in surface, and opt in.
- After opting in, they see their pitch summary, the **"find my founders"** button, and on press a results page of 3–7 adjacent founder pitches (or an honest cold-start empty state if the corpus is too small).
- They can opt back out from the results page.
- The results page contains no likes, comments, ranks, or AI-written content. The visible-string allowlist check passes.
- 3+ founders have opted in to be discoverable in the first week of the surface being live (success signal — measure manually, no dashboard needed in v1).
