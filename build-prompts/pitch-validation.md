## Anti-patterns — do not repeat

- **Don't frame misalignment as bad.** A marker landing in `--logo-sky` while the rest cluster in `--logo-pink` is *not* a bug, a warning, or an error — *"it just means it didn't quite follow the rest of the pitch."* Never the language of *"wrong"*, *"off"*, *"weak"*, *"misaligned with best practice"*, *"low confidence"*. Never red error styling, never warning icons, never strikethroughs.
- **Don't give a score or a grade.** No `7/10`, no `Sharpness: 84%`, no `Strong / Weak`, no readiness percentage, no count of outlier slides. The spectrum IS the signal.
- **Don't write words for the founder.** The validation flow reuses `writing.js`'s engine, which already enforces `verifyFounderOnly`. The coherence endpoint returns only per-heading color positions, never alternate phrasing. The classifier for routing writings into decks returns only verbatim substrings from the founder's text, never generated copy. AI classifies, clusters, and routes — never authors.
- **Don't compare the founder to other founders.** No benchmarks, no peer averages. The spectrum measures the founder's eleven slides against each other; the per-deck classification measures the founder's writings against the targets the founder named.
- **Don't lock the deck behind the paywall.** The default deck (the founder's existing pitch) is free; reading it, exporting it, writing into it, validating it, and seeing its spectrum are all free. Only *additional* decks (creating new ones, switching to them) require payment.
- **Don't ship a new editor.** The validation flow is the existing `writing.js` flow with the deck hidden and a different opening question. Writing into any deck (default or paid) is also the same `writing.js` flow — the deck-switcher decides which tree the classifier writes into. Do not duplicate the writing engine.
- **Don't ship celebration UI on payment.** No confetti when the founder pays. No "Congrats — you're a Pro!" modal. After successful payment, the deck-switcher chrome appears in its slot and the `Add a deck` affordance becomes interactive. That's the entire transition.
- **Don't ship motion.** The current design system says: *"Motion: none. State changes are instant by design. No `--motion-*` tokens exist. If you reach for a transition or an animation timing, reconsider — the spirit of the app is 'a quiet place to be on the web,' and nothing here performs."* The validation flow opens by direct render — no fade-in, no slide, no pulse. v0.100's dissolve transition and pulse are gone.
- **Don't break the shadow rule.** Shadows live on buttons only. Cards, panels, modals, the spectrum bar, the deck switcher, the payment screen — all stay flat, separated by `--color-border` (`#ede8e0`) hairlines.
- **Don't use pure white.** Page is `#fffdf7`. Cards step UP to `#fff9f0` (warmer, not lighter). Modals and screens stay in this palette. v0.100's `#fefefe` near-pure-white is dead.
- **Don't ship a wizard with named steps.** No *"Step 2 of 4: Read the spectrum"*. Each surface is one scroll or one focus.
- **Don't gate the daily return loop behind a notification.** No push, no email reminder, no "come back tomorrow" nag. The founder returns because the spectrum or their new deck is interesting — or they don't.
- **Don't auto-route writing into a deck the founder didn't intend.** When a paid founder has multiple decks, the deck-switcher's `activeId` is the *only* authority for which deck receives new writing. There's no AI guessing across decks based on content; if the founder wants a writing to go to a different deck, they switch decks before they write. (Cross-deck routing — "this writing applies to two decks" — is explicitly out of v1.)
- **Don't ship emoji or exclamation points.** Carries from the design system's *"What it never does"* rule. The copy carries the warmth.

## What you're building, in one paragraph

When a founder has been writing in tinker until every one of the eleven deck headings on their default deck has at least one verbatim phrase under it, a **validation tile** appears on the welcome page. Clicking it opens the existing `writing.js` question-answer flow — same `Next →` and `This is everything →` footer — with the deck/sidebar hidden and a validation-flavored opening question. After they press `This is everything →`, the stitched essay routes to a **review screen** that renders one visualization: a horizontal tinker-rainbow spectrum bar with eleven markers, placed by the coherence classifier (`claude-haiku-4-5-20251001`) according to which color band each slide belongs to in this founder's voice. The review screen's footer has two buttons: `Sharpen for $9` (primary) and `Keep` (secondary). `Keep` returns to the base flow. `Sharpen for $9` opens a small Stripe Checkout screen (Apple Pay enabled), and on successful payment the **sharpening feature** unlocks: the founder can now create *additional* pitch decks by typing the name of an investor or venture partner they're targeting, switch between decks via a chrome switcher, and route all their subsequent writing into whichever deck is active. Each deck has its own `DECK_HEADINGS` tree, its own validation flow, and its own spectrum visualization. The server uses Claude with web search to find that target's site and distill its voice into a `sourceContext` blob; the distilled context biases the classifier so writings get routed *toward* the language of that target investor without anyone authoring new copy. The distilled context is cached in Postgres and reused across all paid users targeting the same name — one fetch per target, reused for everyone. The default deck remains free and complete — multi-deck management is the only thing payment unlocks.

## Phase plan

- **Single-phase build, three feature blocks shippable in order.** All three target web/PWA via `src/renderer/`; no Electron-specific code, no Capacitor-specific code.
  - **Block A:** the validation flow + review screen (build steps 1–5). The free-tier surface. Ships first; can ship before B or C is started.
  - **Block B:** the payment flow (build step 6). Stripe Checkout with Apple Pay enabled, server-side subscription state. Pause for founder confirmation of price ($9/mo), Apple Pay availability, and `priceId` before proceeding.
  - **Block C:** the multi-deck management (build steps 7–10). Storage migration, deck switcher, name-based add-deck flow with server-side web search + shared cache, context-aware classification. The largest block; only enabled for paid users.

### Block C — multi-pitch sharpening

7. **Migrate storage from single-deck to multi-deck.** The current `tinker.tree.v1` localStorage blob holds the founder's entire pitch as a flat `{ "<deckHeading>": [phrases...], "_meta": {...} }` shape. v0.102 introduces a parent layer.

   **New shape — `tinker.decks.v1`:**
   ```
   {
     decks: {
       "default": {
         id: "default",
         name: "[NEEDS INPUT: founder's name for their default deck — could just be 'My pitch']",
         sourceUrl: null,
         sourceContext: null,
         createdAt: <ts>,
         tree: { "<deckHeading>": [...], "_meta": {...} }
       },
       "deck-<uuid>": {
         id: "deck-<uuid>",
         name: "<canonical name resolved by web search — see step 9>",
         sourceUrl: "https://acme.vc",
         sourceContext: "<scraped + cleaned page content, ≤ 8000 chars>",
         createdAt: <ts>,
         tree: { "<deckHeading>": [...], "_meta": {...} }
       },
       ...
     },
     activeId: "default",
     _meta: { schemaVersion: 1 }
   }
   ```

   **One-shot migration** runs once per browser on app boot, gated by a `tinker.decks.migration.v1` flag. If `tinker.decks.v1` does not exist and `tinker.tree.v1` does, create `tinker.decks.v1 = { decks: { default: { id: "default", name: "My pitch", sourceUrl: null, sourceContext: null, createdAt: now(), tree: <existing tinker.tree.v1 blob> } }, activeId: "default", _meta: { schemaVersion: 1 } }`, then delete `tinker.tree.v1`. Set the flag. Silent — no UI prompt.

   **All read sites that previously hit `tinker.tree.v1` directly** must now read through a new accessor module `src/renderer/decks.js` that exposes:

Normalizes the input name to a cache key (`lowercase`, `trim`, collapse internal whitespace, strip punctuation). Looks up the `pitch_contexts` table by `normalized_name`.    **Postgres schema (new table — write a migration):**

   ```
   CREATE TABLE pitch_contexts (
     id              BIGSERIAL PRIMARY KEY,
     normalized_name TEXT UNIQUE NOT NULL,
     raw_name        TEXT NOT NULL,
     canonical_name  TEXT NOT NULL,
     source_url      TEXT,
     source_context  TEXT NOT NULL DEFAULT '',
     fetched_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
     created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
   );
   CREATE INDEX pitch_contexts_normalized_name_idx ON pitch_contexts (normalized_name);
   ```

Mitigations: (a) accept it — the cache is a feature, you get what your peers got; (b) show the resolved `canonicalName` + `sourceUrl` to the founder as part of the success state, with a small `Wrong one?` text affordance that re-fetches with a clarifying prompt. v1 default: (a). Confirm.
- **What does "voice mode" mean to the coherence model?** Step 4's classifier places each heading into one of seven palette colors based on "voice mode", but the meaning is currently emergent — Sonnet decides it per session. Should there be a fixed taxonomy (e.g. *concrete / abstract / emotional / analytical / personal / strategic / aspirational*)?
- **Is a trajectory view in v1?** "Drift narrows over time" was the magnet. Minimum is "yesterday's spectrum is reachable from somewhere"; maximum is a chart of marker convergence over N days. Pick a v1 surface, or defer.
- **How does the founder remove / rename a deck?** The current spec has no delete/rename UI. Probably needed for v1; not yet specified.
- **What happens to a paid founder whose subscription lapses?** Spec needs: their additional decks become read-only? hidden until they re-subscribe? deleted after N days? The default deck stays accessible regardless.
