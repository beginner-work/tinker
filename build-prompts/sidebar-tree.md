# Build the tinker sidebar revamp

> Version: v0.103
> Generated by the founder-package skill (product spec flow).

Build the v1 of the revamped tinker sidebar from this prompt. The founder has worked through a guided interview that distilled the idea into the structure below; this is the imperative form a build agent executes against.

**This revision (v0.103) replaces the v0.102 design.** Two things changed:

1. **The sidebar mirrors `pitch-deck.md`, not the user's writing locations.** The top tier is the seven deck headings (The Problem, Why Now?, The Product, How We Make Money, The Moat, Competition, The Ask). Under each heading sit verbatim phrases lifted from the writings the user has done about that beat. Earth / Seed / Growth vector are out as the sidebar's structuring concept.
2. **A heading only appears once the user has written something the classifier maps to it.** The cold-start sidebar is empty (brand above Account, same as v0.102). The hero moment is the unlock: the user writes about Why Now and a new heading lands in their sidebar tomorrow.

v0.102's data migration also broke writings on returning users (the `seed → earth` rename lost tags); v0.103 includes a recovery step before the new shape is built.

This is still a one-shot revamp. There is no Phase 2, no Electron-only step, no native mobile work. Ship it all to web/PWA, end to end.

## Vocabulary — read this section first

The v0.102 vocabulary collapses. Here's what survives v0.103:

| Concept | What it is | Where it lives |
|---|---|---|
| **Deck heading** | One of the seven fixed strings from `pitch-deck.md`: *The Problem*, *Why Now?*, *The Product*, *How We Make Money*, *The Moat*, *Competition*, *The Ask*. The top tier of the new sidebar. | Hard-coded in the renderer. Order is fixed and matches the deck. The seven literals are AI/developer-authored, on the chrome allowlist; nothing else in the tree is. |
| **Phrase** | A verbatim substring of one of the user's drafts or essays, identified by `{ writingId, offset, length }`, displayed as an inner row under a deck heading. The user's own words, surfaced unmodified. | Computed by the classifier function (see step 4); persisted in `tinker.tree.v1` in localStorage; synced via `sync.js`. |
| **Writing** | An individual draft or essay (the unit the founder actually composes). | `tinker.drafts.v1`, `tinker.essays.v1`. Unchanged by v0.103 except for the recovery step in (1) below. |
| **Earth** | Where the user wrote from (e.g. `"home"`, `"cafe"`). **Metadata only.** Carried on each writing. **Does not drive the sidebar** anymore. The welcome-grid place tiles continue to write into this field as they do today. | `tinker.earths.v1` in localStorage; `draft.earth`, `essay.earth` on writings. Same key as after v0.102's rename — do not rename again. |

**Seed (cluster) and Growth vector are dead concepts.** The v0.102 design used them as the middle and leaf tiers of a three-tier tree clustered under Earth. v0.103 throws this out. Strip them from the code, the storage, the CSS class names. There is no AI clustering anymore — only AI classification (writing → deck heading + chosen verbatim phrase). Two tiers, not three.

The seven deck headings are spelled exactly as they appear in `pitch-deck.md` slide titles, including the question mark on *Why Now?* and the capitalization on *How We Make Money*. The renderer holds them as a const array in this order; the classifier returns one of these seven strings (or null for "doesn't fit any") and the renderer matches against the const. No alternate spellings, no case-insensitive comparisons.

## Anti-patterns — do not repeat

- **Don't reintroduce Seed or Growth vector as visible concepts.** They're gone from the sidebar's structuring vocabulary. No three-tier tree. No clustering inside an Earth. No row class named `.sidebar__seed` or `.sidebar__growth-vector`. If the v0.102 code shipped any of these, strip them; the rename and rebuild are the work.
- **Don't reintroduce numbering.** The quiet `01..NN` ordinals on Earth and Seed rows from v0.102 are gone. The deck headings carry their own narrative order (The Problem comes first because that's where the deck starts); rendering numbers on top of named headings is noise. No leading ordinals on deck-heading rows, no ordinals on phrase rows.
- **Don't author labels at the phrase tier.** Every inner phrase row must be a verbatim substring of one of the user's drafts or essays, validated at the API layer by reading the substring at the returned `{ writingId, offset, length }`. A label like "your problem in a nutshell" or "thoughts on the moat" is a bug; a label like "the barber gave me a hundred bucks" is correct.
- **Don't paraphrase or normalize the deck headings either.** The seven literals are exactly as in `pitch-deck.md`. *Why Now?* has a question mark. *The Moat* uses "The". *How We Make Money* is Title Case. Don't lowercase, don't drop articles, don't translate. The classifier returns one of the seven; the renderer matches against the const. The strings are the contract.
- **Don't render a deck heading the user hasn't written about yet.** The unlock IS the hero moment: a new heading appears in the sidebar tomorrow because the user wrote about it today. Rendering all seven dimmed, or rendering a placeholder for un-unlocked ones, kills the moment. Cold-start is empty. Headings light up one at a time, in whatever order the user's writing causes them to.
- **Don't ship a "next stage" affordance or any prompt to move forward.** No "Next: Why Now", no "You're 3 of 7 through your deck", no progress meters, no "what's next" beckoning. The curriculum is composed by the user's writing, not advanced by a button.
- **Don't ship judgmental or AI-narrator phrasing anywhere.** Carried from v0.102: no "we noticed you've been writing about…", no "you've reached The Product stage". The mirror reflects; it does not commentate.
- **Don't introduce new fonts, colors, button visuals, icon libraries, or a CSS framework.** Carried from v0.102. Visual canon is `src/renderer/styles.css` + `src/renderer/design-tokens.css` + `src/renderer/tokens/rainbow-web.json`. Deck-heading rows and phrase rows reuse `.sidebar__account-item`'s sizing/hover/spacing.
- **Don't introduce a chat or onboarding flow.** Carried from v0.102. The sidebar is composed; the user doesn't talk to it.
- **Don't classify across users.** Each user's classifier output is derived only from their own writings. No cross-user signal, no shared taxonomy.
- **Don't include hidden writings in classification input.** The existing `tinker.earths.hidden.v1` set is excluded. Hidden things stay hidden.
- **Don't ship native mobile or Electron in this revamp.** Web/PWA only. If a code path is Electron-only or Capacitor-only, leave it as-is.
- **Don't ship before recovering the v0.102 migration's data corruption.** Step 1 below is non-negotiable. If a returning user opens the new build and finds their writings untagged or missing, the revamp failed regardless of how good the new sidebar looks.
- **Don't ship a visible "Phrases" or "Writings" sub-header under a deck heading.** A `<nav aria-label="Pitch deck">` is fine for accessibility (sr-only). Visible chrome labels for the inner tier are not. The deck heading and the verbatim phrases are the content; nothing else.
- **Don't render a deck heading that has zero phrases under it.** Same rule as v0.102's empty-branch rule: if classification produced no surviving phrases for a heading, that heading is not rendered. (The unlock is the first phrase landing under a heading.)

## What you're building, in one paragraph

A founder opens tinker. The sidebar mirrors the pitch deck. The first time they write something the classifier maps to *The Problem*, that heading appears in their sidebar — and under it, a single verbatim phrase from what they wrote. The next session they write about why now; a *Why Now?* row appears, with one of their phrases under it. Over weeks, the seven headings light up one at a time, each populated with phrases lifted unedited from their own writings. The order of the headings stays fixed (the deck's order); only which ones are visible changes, and the inner phrases under each. The whole tree is computed on the server when a writing session closes, cached locally for instant render, persisted across devices via the existing sync layer. Visually it lives inside the same `.sidebar` shell that's there today — same warm-cream surface, brand block above, Account block below — and reads as a personal deck the founder is mid-way through writing.

## Mood — how it should feel

The tree is **a curriculum just for you** (carried from v0.102). The fixed deck headings are the syllabus; the verbatim phrases are the syllabus filled in with the founder's own work. When their eye lands on the sidebar, the read is: *"someone — quietly — laid this out for me, from my own words, in an order that's mine."*

What carries this mood in v0.103 (with numbering gone):

- **The deck headings are the order.** The Problem first, The Ask last. No `01..07`, no progress meter — the named beats do the work numbers would have done.
- **The unlock is the moment.** A heading appears in the sidebar because the user wrote about it. The sidebar's growth IS the curriculum advancing. Nothing prompts them forward; their writing pulls the next heading into view.
- **Phrases are unedited.** Same as v0.102's verbatim rule applied to growth vectors — the phrase under a deck heading is one of the user's own sentences, lifted whole. No AI smoothing, no truncation past `…`, no normalization.
- **Active state is whisper-quiet.** Same active-row treatment as v0.102 — only the currently-open row carries the active background; ancestor rows are inert.

What this mood is NOT (carried from v0.102, plus v0.103-specific):
- Not progress tracking. No "3 of 7", no checkmarks, no percentages, no "stages complete".
- Not gamification. No streaks, no XP, no badges, no "you unlocked".
- Not an editor's voice. No narration around the unlock — the heading just appears next time the sidebar renders.
- Not a productivity sidebar. No "Recently used", no "Pinned", no group headers like "In progress" / "Complete".
- Not a deck preview. The sidebar shows what the user has written, not the slides from the original `pitch-deck.md`. The seven headings come from the deck; the bodies of those slides do not.

## The tree, drawn

```
The Problem
    "the barber gave me a hundred bucks"
    "I feel like I've worked so hard, but I'm still stressed"
Why Now?
    "the sprint towards figuring out what we can do is insane"
The Product
    "you come because they have what you need"
    "you stay because everyone's there"
```

(*Cold-start state* has no rows; the tree `<nav>` is hidden, brand sits directly above Account. *Partial state* shows only the headings the user has written into — so a user who's written about *The Problem* and *The Product* but not the others sees exactly those two rows, with The Problem above The Product because that's the deck's order, regardless of which one the user wrote about first.)

- **Deck-heading rows** are always rendered when the user has at least one phrase under that heading. Order is fixed: deck order, top to bottom. Tap to expand/collapse the heading's phrase list. Default state on first paint: the most-recently-touched heading is expanded; the others are collapsed.
- **Phrase rows** appear under an expanded deck heading. The number per heading is bounded by what classification surfaces — typically 2–5 in steady state, no hard cap below five but the function trims to the five most-recent if more than five would land. Tap a phrase to open the underlying writing in the stage area (same pattern as opening a writing today). One phrase = one writing (no badge, no count, no multi-writing picker — v0.102's `(N)` badge belongs to the dead three-tier model and does not return).
- **Active state.** Only the currently-open row (deck heading, phrase, or the writing in the stage area) carries the active background. Ancestor rows do not get a path-highlight.
- **Loading state.** While classification is running after a writing-session close, the existing tree stays rendered. If classification produces a new heading (one that wasn't in the cached tree), the tree re-renders with that heading inserted in its deck-order position. No spinner, no "thinking..." text, no toast announcing the unlock. The new row just appears.
- **Failure state.** If classification fails, the tree silently falls back to its last cached state. A tiny `↻` affordance appears next to the topmost deck-heading row so the founder can retry manually. (Same fallback pattern as v0.102.)
- **Hidden writings.** Excluded from classification input. The existing "Hidden" surface stays where it is in the current sidebar / app — do not move it.
