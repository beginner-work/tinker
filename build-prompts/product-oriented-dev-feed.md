# Build tinker product-oriented development feed (GitHub alternative)

> Version: v0.100
> Generated by the founder-package skill (product spec flow).

Build the v1 of the product-oriented development feed from this prompt. The
founder worked through a guided interview that distilled the idea into the
structure below; this is the imperative form.

**Process constraint (founder):** build view by view; pause for review with
Cursor native screenshots/videos after each view. Do not ship the next view
until the founder reviews.

## Anti-patterns — do not repeat

- **Don't put AI-written content on the page.** Every visible string is either
  a verbatim quote from the founder's pitch / writings / reflections, or a
  fixed UI string from the allowlist below.
- **Don't share source code in the feed.** The feed shows *progress of source
  code as it relates to development and the pitch* — not diffs, not file trees
  as the product.
- **Don't invent a new visual language.** Inherit tinker's chrome (dark-mode
  first for this native shell).
- **Don't build a chat layout.** This is a feed they read, not a conversation.
- **Don't put cloud LLM authorship on founder words.** On-device Google Gemma
  may *organize* and *transcribe*; it must not author copy that lands on screen
  as the founder's voice.
- **Don't skip the MCP hub.** Repositories are pulled / registered through the
  beginner MCP — that is the source of truth for repo install and pull.

## What you're building, in one paragraph

A native **iOS Expo** app that builds off tinker: founders write source ideas
and develop web/native repositories in tinker; the MCP is the hub that pulls
repositories as the source of truth; the app shows a LinkedIn-style feed of
other founders' *development progress* (product-oriented, no source sharing)
and a view that maps repository source to founder source ideas (coverage /
misalignment). First open shows a quote from the person themselves (pitch
reflections / writings). Dark mode first. On-device Google Gemma (highest
capable edge model that fits the device) handles transcriptions and
organization of founder source ideas and repository source code.

## Phase plan

- **Single-phase build for v1.** Target native iOS via Expo. Web export is
  allowed only as a screenshot/review surface for Cursor reviews on
  non-macOS agents. Capacitor paths in this repo stay untouched unless the
  founder later asks to unify.

## Build sequence

1. **View 1 — First open + dark feed shell.** Expo app under `apps/native/`.
   Dark mode default. First screen: a quote from the founder's own pitch /
   writings. Then the empty/home feed chrome in LinkedIn-style layout, tinker
   feel (welcoming and grounded, generous padding). Fixed UI allowlist only.
   **CHECKPOINT — stop and report.** Screenshot/video via Cursor; pause for
   founder review before View 2.

2. **View 2 — Connect repo / pitch.** UI to connect a pitch (from tinker pitch
   store) and a repository (installed via MCP hub tool). Shows connection
   state only — no AI prose.
   **CHECKPOINT — pause for review.**

3. **View 3 — Coverage view.** Examine repository source against founder
   source ideas; show covered / unaligned sections as a view (not a chat).
   Gemma on-device organizes the mapping; labels on screen are allowlisted or
   verbatim founder phrases / file path names from the repo.
   **CHECKPOINT — pause for review.**

4. **View 4 — Progress feed.** LinkedIn-style feed of other founders'
   development progress (pitch-related), without source code. Return loop:
   someone they care about is here.
   **CHECKPOINT — pause for review.**

5. **MCP repo hub.** In the `mcp` repo: tools to register, list, and pull
   repository manifests (source of truth for "install the MCP tool → that idea
   is your repo source"). D1 migration for `repositories` (+ optional
   `progress_events` for the feed).
   **CHECKPOINT — pause for review.**

6. **On-device Gemma wiring.** Highest capable on-device Gemma that runs on
   target iPhone class via Expo native module (e.g. LiteRT-LM / MediaPipe path).
   Used for transcription + organization only. Expo Go unsupported; dev client
   required.
   **CHECKPOINT — pause for review.**

## Constraints (non-negotiable)

- **No AI-written content on the page.** Visible-string allowlist applies.
- **Not a chat.** Feed they read; no persistent composer thread as the product.
- **Inside tinker's visual canon**, dark-mode-first for this Expo shell.
- **Welcoming and grounded** — generous padding; soft press; no bouncy motion.
- **MCP is the repo hub** — products do not invent a parallel repo store.
- **On-device Gemma** for transcription + organization of founder ideas + repo
  source; highest capable edge model that fits the device.
- **Build view by view; pause with screenshots/videos for review.**
- **Pitch bottleneck is real.** First open must make "building a product of
  your own" legible via the person's own words.
