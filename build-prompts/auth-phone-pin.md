# Build the tinker phone/PIN sign-in gate

> Version: v0.100
> Generated by the founder-package skill (product spec flow).
> Reconstructed from shipped code by the build-prompts audit (2026-05).

Build the sign-in gate that sits in front of the renderer on the plain web
build: a phone-then-PIN screen backed by Stytch SMS OTP, returning a long-lived
Stytch session token that the renderer stores in `localStorage` and sends as a
Bearer token to every `api/*` function. The functions re-validate the token
against Stytch server-side and call Anthropic with the server-held
`ANTHROPIC_API_KEY` — the browser never sees the key. On Electron desktop (which
has its own `ANTHROPIC_API_KEY` env var) and on Capacitor mobile (which pulls a
key from `localStorage`) the gate is loaded but skipped.

## Anti-patterns — do not repeat

- **Don't store or trust an `exp` clock in the client.** The value in
  `tinker_jwt` is now Stytch's opaque 30-day `session_token`, not a JWT with a
  readable expiry. Validation is server-side on every request via Stytch's
  `/sessions/authenticate`; the server is the source of truth. (The README still
  describes returning a `session_jwt` — that's stale: `verify.js` returns the
  `session_token` precisely because the 5-minute JWT clock used to log people out
  after a reload. Do not regress to handing out the short-lived JWT.)
- **Don't show the gate in the wrong runtime.** Only the plain web build shows it
  — `auth.js` returns early unless `<html>` has the `on-web` class (set by
  `platform-mobile.js`) and `window.tinker.supportsWebview !== true` (Electron's
  backstop). Capacitor and Electron load the file but never render the gate.
- **Don't reload the page on a mid-session 401.** A reload reads as "I submitted
  something and got bounced to login." Instead `platform-mobile.js` clears the
  token and calls `window.tinkerAuth.showGate()` to surface the gate in place.
- **Don't add an allowlist, invite code, or email/password path.** v1 is
  phone-OTP only: anyone who completes Stytch SMS-OTP is in. The URL isn't
  advertised, the page is `noindex`, and Stytch is the authentication boundary
  (see the comment atop `api/auth/phone/request.js`). Passwords, magic links, and
  OAuth are explicitly out of scope (`api/_lib/stytch.js`).
- **Don't put the Anthropic key in the browser.** Every Claude call on the web
  build is proxied through `api/*` with the server-side `ANTHROPIC_API_KEY`; the
  bundle holds only the Stytch session token.
- **Don't design a new sign-in screen.** The gate markup already lives in
  `index.html` (`#auth-gate`) and is styled by `styles.css`. Reuse the rainbow
  globe mark and the existing pill inputs; sign-up and login share one screen.

## Read first

- `src/renderer/auth.js` — the gate controller. Token store
  `window.tinkerAuth` (`get/set token`, `signOut()`, `showGate()`), the
  `isWebPlatform()` guard, the two-step phone→PIN form wiring, and the
  legacy-JWT scrub (`looksLikeLegacyJwt` drops any three-segment dotted value
  left over from before the switch to session tokens). Storage keys:
  `tinker_jwt` (token), `tinker_phone`, `tinker_phone_id`.
- `src/renderer/index.html` (the `#auth-gate` block) — the markup the controller
  drives: `#auth-phone-form` (`#auth-phone-input`, +1 prefix), `#auth-pin-form`
  (`#auth-pin-input`, 6-digit), `#auth-status`, `#auth-back`, the
  `[data-step-title]` / `[data-step-lede]` slots, and the shared sign-up/login
  fineprint. Loaded after `platform-mobile.js` so the `on-web` class is already
  set.
- `src/renderer/platform-mobile.js` — sets `on-web` / `on-capacitor`, and on a
  proxied-call 401 clears `tinker_jwt` and calls `window.tinkerAuth.showGate()`.
  The Claude proxy (`callClaude` → `POST /api/claude/converse`) is the consumer
  of the Bearer token.
- `src/renderer/pwa-session.js` — runs before `auth.js`; imports `?#ts=<jwt>`
  off the iOS PWA launch URL into `tinker_jwt`, and on `tinker:auth-changed`
  folds the fresh token into the manifest `start_url` so an immediate "Add to
  Home Screen" keeps the session. `auth.js` dispatches `tinker:auth-changed`
  right after a successful verify. (Full PWA detail: `app-shell-and-pwa.md`.)
- `api/auth/phone/request.js` — `POST { phone }` → `{ phone_id, isNew }`. Calls
  `sendSmsOtp`. POST-only; validates `phone` is a non-empty string; maps Stytch
  errors to their status (else 502).
- `api/auth/phone/verify.js` — `POST { phone_id, pin }` (accepts legacy `code`
  alias) → `{ token, isNew }`. Calls `authenticateOtp`, returns the
  `session_token` as `token`, infers `isNew` from the user's `created_at`
  (`looksFreshlyCreated`, < 2 min old).
- `api/_lib/stytch.js` — the dependency-free Stytch REST client. `readEnv`
  (`STYTCH_PROJECT_ID` + `STYTCH_SECRET`), `baseUrlFor` (test vs. live base from
  the project-id prefix), `toE164` (10-digit US → `+1…`), `sendSmsOtp`
  (`/v1/otps/sms/login_or_create`, 10-min expiry), `authenticateOtp`
  (`/v1/otps/authenticate`, 30-day session), and `authenticateSession` (validates
  whichever bearer the client holds — `session_token` or legacy `session_jwt` —
  at `/v1/sessions/authenticate`). This last function is the seam every other
  `api/*` endpoint shares (it's what `api/_lib/user-data.js` calls).
- `api/_lib/log.js` — `withResponseLogging`, the wrapper every endpoint uses.
- `README.md` (lines 43–98) — the four-step auth flow, the required env vars
  (`STYTCH_PROJECT_ID`, `STYTCH_SECRET`, `ANTHROPIC_API_KEY`, `DATABASE_URL`),
  the local run target (`npx vercel dev`), and `window.tinkerAuth.signOut()`.
- `package.json`, `vercel.json` — run targets and the `api/` serverless layer.

## What you're building, in one paragraph

`auth.js` runs only on the plain web build. On load it scrubs any stale
JWT-shaped token, and if there's no `tinker_jwt` it reveals `#auth-gate` (adding
`auth-gating` to `<html>`). The gate is a two-step pill form: the founder enters
a 10-digit US phone, the controller POSTs `/api/auth/phone/request`, stashes the
returned `phone_id` under `tinker_phone_id`, and advances to the PIN step; the
founder enters the 6-digit code, the controller POSTs `/api/auth/phone/verify`,
stores the returned `session_token` as `tinker_jwt`, dispatches
`tinker:auth-changed` (so `pwa-session.js` refreshes the manifest and `sync.js`
hydrates), shows a one-beat welcome message, and drops the gate. Server-side,
two thin Vercel functions wrap `api/_lib/stytch.js`: `request.js` triggers the
SMS OTP and returns `phone_id`; `verify.js` authenticates the PIN and returns
the 30-day `session_token`. Every other `api/*` function re-validates that token
through `authenticateSession` and only then calls Anthropic with the server-side
key. The same Stytch project (test vs. live, chosen by the project-id prefix) and
the same `tinker_jwt` key are shared by the desktop/mobile shells, which skip the
gate entirely.

## Build sequence

1. **The Stytch client — `api/_lib/stytch.js`.** Build the dependency-free REST
   wrapper: `readEnv()` (throws 503 if `STYTCH_PROJECT_ID`/`STYTCH_SECRET`
   missing), `baseUrlFor()` (`project-test-*` → `test.stytch.com`, else
   `api.stytch.com`), a `stytchPost(path, body)` helper using HTTP Basic auth
   `projectId:secret`, `toE164()` (10-digit → `+1…`; 11-digit leading-1 →
   `+…`; else 400), `sendSmsOtp(phone)` → `/v1/otps/sms/login_or_create`
   (`expiration_minutes: 10`), `authenticateOtp(phoneId, code)` →
   `/v1/otps/authenticate` (`method_id`, `code`, `session_duration_minutes:
   60*24*30`; validates a 6-digit code), and `authenticateSession(bearer)` →
   `/v1/sessions/authenticate` (sends `session_jwt` if the bearer contains a
   `.`, else `session_token`; maps any 4xx to a 401 "Session expired."). Export
   all of them.
   **CHECKPOINT — stop and report.** Confirm the env-missing branch returns 503
   and the test/live base-URL split is keyed off the project-id prefix. Get a
   real `STYTCH_PROJECT_ID`/`STYTCH_SECRET` into the Vercel env before testing a
   live SMS.

2. **The two endpoints.** Build `api/auth/phone/request.js` (POST-only; parse
   the body defensively; require a non-empty string `phone`; call `sendSmsOtp`;
   reply `{ phone_id, isNew: Boolean(user_created) }`; map Stytch errors to
   their status, else 502) and `api/auth/phone/verify.js` (POST-only; read
   `phone_id` and `pin || code`; call `authenticateOtp`; 502 if no
   `session_token` comes back; reply `{ token: session_token, isNew:
   looksFreshlyCreated(user) }`). Wrap both in `withResponseLogging`.

3. **The client gate — `auth.js`.** Build `window.tinkerAuth` (`token`
   getter/setter over `tinker_jwt`, `signOut()` that clears it and reloads,
   `showGate()` exposed for mid-session reauth). Guard with `isWebPlatform()`
   (return early unless `<html>.on-web` and not Electron). On load: drop any
   `looksLikeLegacyJwt` value, and if there's no token call `showGate()`
   (reveal `#auth-gate`, add `auth-gating` to `<html>`, focus the phone input).
   Wire the phone form (live-format input to `(555) 000-0000`; on submit require
   10 digits, POST `/api/auth/phone/request`, save `phone`/`phone_id`, advance
   to the PIN step via `showStep("pin")`), the PIN form (require the stashed
   `phone_id` and a 6-digit code, POST `/api/auth/phone/verify`, store
   `data.token` as the session, remove `phone_id`, dispatch
   `tinker:auth-changed`, show the `isNew ? "Welcome to tinker!" : "Welcome
   back."` beat, then drop the gate after ~350ms), and the `#auth-back` link
   (return to the phone step). Use the `[data-step-title]`/`[data-step-lede]`
   slots for step copy.
   **CHECKPOINT — stop and report.** On `npx vercel dev`, confirm: a fresh load
   with no token shows the gate; entering a real phone sends an SMS and advances
   to the PIN step; entering the code stores `tinker_jwt`, fires
   `tinker:auth-changed`, and drops the gate; reloading stays signed in (no
   re-verify); a wrong code surfaces the error and reselects the PIN input.

4. **The shared validation seam.** Confirm every protected `api/*` function
   re-validates through `authenticateSession` and pulls the user id out of the
   session response (the pattern lives in `api/_lib/user-data.js`'s
   `resolveUserId` and in `api/claude/converse.js`). The browser sends
   `Authorization: Bearer <tinker_jwt>`; the server authenticates, then calls
   Anthropic with `ANTHROPIC_API_KEY`. No endpoint trusts the client's claim of
   identity.

## Constraints (non-negotiable)

- **Web-only gate.** `auth.js` renders the gate only when `<html>.on-web` is set
  and the runtime isn't Electron (`window.tinker.supportsWebview !== true`).
  Capacitor and Electron load the file but skip the gate.
- **Server-side token validation, no client clock.** The stored value is the
  opaque Stytch `session_token`; validity is decided by
  `/sessions/authenticate` on every request. Never parse an `exp` client-side.
  `verify.js` returns the `session_token` (30-day), not the 5-minute
  `session_jwt`.
- **One token key: `tinker_jwt`.** Shared with `pwa-session.js`, `sync.js`, and
  the `platform-mobile.js` proxy. Sent as a Bearer token to `api/*`.
- **The Anthropic key stays server-side.** `ANTHROPIC_API_KEY` lives only in the
  Vercel env; the browser proxies Claude through `api/*`. No key in the bundle on
  the web build.
- **Phone-OTP only.** No allowlist, invite code, email/password, magic link, or
  OAuth. Anyone completing Stytch SMS-OTP is in; the page is `noindex` and the
  URL is unadvertised.
- **Test/live base URL is derived, not configured.** `baseUrlFor` reads the
  `project-test-*` vs. `project-live-*` prefix; don't add a separate base-URL env
  var.
- **Mid-session 401 surfaces the gate in place.** Clear the token and call
  `showGate()`; never reload the page to re-auth.
- **Reuse the shipped gate markup and chrome.** `#auth-gate` in `index.html`,
  styled by `styles.css`, with the rainbow globe mark. Sign-up and login share
  the one screen.

## Done when

- A web visitor with no token sees `#auth-gate`; entering a 10-digit US phone
  triggers a Stytch SMS and advances to the PIN step.
- Entering the 6-digit code stores the Stytch `session_token` under `tinker_jwt`,
  dispatches `tinker:auth-changed`, shows the new-vs-returning welcome beat, and
  drops the gate.
- Reloading keeps the session (no re-verify); a wrong code shows the error and
  reselects the PIN field; `#auth-back` returns to the phone step.
- `request.js` returns `{ phone_id, isNew }` and `verify.js` returns `{ token,
  isNew }`; both reject non-POST and map Stytch errors to sane statuses; missing
  Stytch env yields 503.
- Every protected `api/*` call validates the Bearer token via
  `authenticateSession` server-side and calls Anthropic with the server-held
  `ANTHROPIC_API_KEY`; the browser never holds the key.
- The gate is skipped on Electron and Capacitor; the same `tinker_jwt` key works
  across all three shells.
- A mid-session 401 (expired/revoked token) surfaces the gate in place instead of
  reloading.
