# Build the tinker pitch system + on-camera script

> Version: v0.100
> Generated by the founder-package skill (product spec flow).
> Reconstructed from shipped code by the build-prompts audit (2026-05).

This spec covers the **pitch store** — the multi-pitch model that holds the
founder's writings as eleven-slide decks — and the **pitch script** view that
turns one pitch into an on-camera storyboard. The founder's drafts and essays
are classified, clustered, and named into pitches by the server; the renderer
owns local selection, title editing, deck expand/collapse, publishing, and the
script surface. Every phrase shown anywhere is a verbatim substring of the
founder's own writing — the AI classifies, clusters, and names, it never
authors. The post-publish arrangement/reveal screen and the social feed are
**separate surfaces** covered by `build-prompts/pitch-review-reveal.md` and
`build-prompts/social-feed.md`; this prompt builds the store and the script and
hands off to them, it does not reimplement them.

## Anti-patterns — do not repeat

- **Don't author at the phrase tier.** Every phrase row, every storyboard line,
  every published beat must be a verbatim substring of one of the founder's
  drafts or essays, resolved at read time from `{ writingId, offset, length }`
  against the live body. A generated summary like "your problem in a nutshell"
  is a bug; `the barber gave me a hundred bucks` is correct. The classifier
  returns `{ deckHeading, phraseText }` where `phraseText` is a verbatim 3–18
  word substring, and the server re-resolves it with `resolvePhraseText` before
  it's ever stored.
- **Don't paraphrase or normalize the eleven `DECK_HEADINGS`.** They are opaque
  literals: `The Problem`, `A Persona`, `Why Now?`, `The Team`, `The Product`,
  `How We Make Money`, `Go to Market`, `The Moat`, `The Vision`, `Competition`,
  `The Ask`. `Why Now?` keeps its question mark; `How We Make Money` stays Title
  Case. Don't lowercase, don't drop articles, don't translate. The renderer
  const, the classifier return value, and the publish validator all reference
  the same fixed list and order.
- **Don't introduce `claude-sonnet-4-6`.** It does not exist in this codebase.
  `api/classify/index.js` and `api/_lib/pitches-clusterer.js` both call
  `claude-haiku-4-5-20251001`. Use that model for the classify and cluster/name
  calls; do not invent or substitute another model id.
- **Don't treat pitches as "main" vs "alt".** Pitches are equal-status and
  renamable. The active selection defaults to the most robust pitch (most deck
  headings covered), not to a privileged "main" one. The `tinkerAltPitches`
  global is only a back-compat alias for `tinkerPitches`; don't build a
  two-class model on top of it.
- **Don't run the organize job on every hydrate or on the boot path.** Boot and
  hydrate only `reloadFromStorage`. Clustering and naming happen server-side in
  `/api/pitches/organize`, triggered by a single debounced POST after writings
  change (`ORGANIZE_DEBOUNCE_MS`, 2500ms).
- **Don't make the script view a publish step.** `pitch-script.js` produces a
  storyboard the founder records a video from. It does not ship anything to the
  daily beginner. Publishing is `publishPitch` → `/api/publish/pitch`; keep the
  two flows distinct.
- **Don't ship more than one phrase per heading.** `MAX_PHRASES_PER_HEADING` is
  `1` in `pitches.js`, `pitches-organizer.js`, and the publish validator. A
  newer phrase for a heading replaces the older one; older drafts of the same
  beat fall away.
- **Don't duplicate the review/reveal screen or the feed here.** When a publish
  or organize round completes, hand the diff to the surfaces those other
  prompts own. This file's job ends at `triggerOrganizeNow` returning a diff and
  `publishPitch` returning a slug.
- **Don't ship motion in the product layer or emoji / exclamation points.**
  Carries from the design system. (See `build-prompts/design-system.md`.)

## Read first

- `pitch-deck.md` (repo root) — the spine. The eleven slide titles are the
  source of truth for `DECK_HEADINGS`, in order, character-for-character. The
  slide bodies are quoted into the classifier prompt as each heading's
  description.
- `src/renderer/pitches.js` — the live store. `tinker.pitches.v1`,
  `DECK_HEADINGS`, the legacy `tinker.tree.v1` one-shot migration, the public
  `window.tinkerPitches` surface (`getPitch`, `getPitches`,
  `findPitchForWriting`, `coveredHeadings`, `setActivePitch`, `getActivePitch`,
  `getActivePitchId`, `upsertPhrase`, `publishPitch`, `getPitchScript`,
  `scheduleOrganize`, `triggerOrganizeNow`, `placementSnapshot`,
  `diffSnapshots`), and the `tinker:pitches-changed` / `tinker:active-pitch-changed`
  events.
- `src/renderer/pitch-script.js` — the on-camera script view. `window.tinkerPitchScript.show(pitchId)`,
  the `STR` string table (`Prepare a script for a video`, `Copy script`,
  `Total`, etc.), `scriptToPlainText`, `formatDuration`. Mounted into
  `<section id="pitch-script">`; reached via `window.tinkerShowPitchScript(pitchId)`
  in `renderer.js`.
- `api/classify/index.js` — the writing → heading classifier. Returns
  `{ deckHeading: string | null, phrase: { writingId, offset, length } | null }`.
  Note: the model returns `{ deckHeading, phraseText }` and the server resolves
  `phraseText` → `{ offset, length }` via `resolvePhraseText`. Model:
  `claude-haiku-4-5-20251001`.
- `api/_lib/pitches-clusterer.js` — shared cluster/name/validate/resolve
  helpers. `DECK_HEADINGS`, `HEADING_DESCRIPTIONS`, `clusterWritings`,
  `nameWritings`, `reconcileClusters`, `validateTitle`, `validateHeading`,
  `fallbackPhrase`, `fallbackHeading`, `resolvePhraseText`, `MAX_WRITINGS`,
  `MAX_BUCKETS`. Both endpoints call these. Model: `claude-haiku-4-5-20251001`.
- `api/_lib/pitches-organizer.js` — the pure `organize({ storedBlob, essays,
  drafts, cluster, name })` entry point; merge semantics, `foldRehomeResults`,
  `pitchesNeedingName`, the empty-pitch prune.
- `api/pitches/organize.js` — the server-driven backend job. Loads `essays`,
  `drafts`, `pitches` from `TinkerUserData`, runs `organize`, persists kind
  `pitches`, returns `{ ok, pitches, updatedAt, summary }`.
- `api/alt-pitches/index.js` — the legacy client-orchestrated round-trip;
  `mode: "cluster"` and `mode: "name"`. Same helpers, same contract; both
  endpoints stay live during the transition.
- `api/publish/pitch.js` — `POST /api/publish/pitch`. Validates `{ title,
  slides }`, derives a slug via `slugify`, calls `renderDeck`, upserts
  `TinkerUserData` under kind `published:<slug>`, returns `{ ok, slug,
  beatCount, updatedAt, readerUrl }`.
- `api/_lib/deck-template.js` — `renderDeck({ title, slides, generatedAt })`.
  Reads the Marp frontmatter from `pitch-deck.md`, renders a cover + one beat
  slide per non-empty heading + a closer, returns `{ markdown, beatCount }`.
- `api/_lib/stytch.js`, `api/_lib/db.js`, `api/_lib/log.js` — auth
  (`authenticateSession`), the Prisma `tinkerUserData` model, and
  `withResponseLogging`. Every endpoint follows this same shape.
- `src/renderer/sync.js` — the localStorage → `/api/user-data/*` round-trip.
  `pitches.js` calls `window.tinkerSync.pushPitches()` on save.
- `build-prompts/pitch-review-reveal.md` and `build-prompts/social-feed.md` —
  the surfaces this prompt hands off to. Read them so you know where the diff
  and the published slug go; do not duplicate their work here.

## What you're building, in one paragraph

The founder writes drafts and essays. A debounced trigger
(`scheduleOrganize`, fired on `tinker:writing-saved` and `tinker:auth-changed`)
POSTs `/api/pitches/organize`, which reads the founder's `essays`, `drafts`, and
existing `pitches` blob out of `TinkerUserData`, finds the writings not yet
slotted into any pitch, clusters them into 1–4 named pitches (each writing
assigned one of the eleven `DECK_HEADINGS` plus a verbatim phrase), names any
pitch whose writing-set drifted, prunes empty pitches, and persists the new
blob. The client folds the server's authoritative blob back into
`tinker.pitches.v1` and re-renders. Each pitch is a full eleven-slide deck with
one verbatim phrase per covered heading; the active pitch defaults to the most
robust one (most `coveredHeadings`). The founder can rename a pitch (a personal
title that sits alongside the AI title), switch the active pitch, publish a
pitch (rendered server-side into a Marp daily-beginner post and stored for the
reader), and open the **pitch script** view — an on-camera storyboard that lists
each covered slide, a suggested speaking duration (~130 wpm), the verbatim
phrases, and a copy-to-clipboard button. Publishing and organize round-trips
return a slug / diff that the review-reveal and feed surfaces consume.

## Build sequence

1. **Stand up the pitch store (`src/renderer/pitches.js`).** Own the
   `tinker.pitches.v1` blob: an array of pitches, each `{ id: "p_<8>", aiTitle,
   personalTitle, aiTitleSourceHash, deck: { [heading]: [phraseRecord] }, meta:
   { mostRecentlyTouched, expanded, lastClassifyFailedAt }, createdAt }`, plus
   `activeId` and `_migratedFromTree`. Hold `DECK_HEADINGS` as an in-module const
   (the eleven literals, in order — duplicated rather than imported so the module
   stands alone). Implement the one-shot migration: if `tinker.pitches.v1` is
   absent but `tinker.tree.v1` exists, wrap the legacy tree as `pitches[0]` with
   null titles and `_migratedFromTree: true`. `normalizeBlob` cleans legacy
   shapes (the old single-`title` field splits into `aiTitle`/`personalTitle`
   based on `autoTitled`), filters phrase records through `isValidPhraseRecord`,
   and validates `activeId`.

2. **Expose the public API on `window.tinkerPitches`.** `getPitches` (returns
   id/aiTitle/personalTitle/displayName/robustness/createdAt), `getPitch`,
   `getActivePitch`, `getActivePitchId`, `setActivePitch` (fires
   `tinker:active-pitch-changed`), `setPersonalTitle` / `renamePitch` (alias),
   `upsertPhrase`, `clearWritingFromAllPitches`, `toggleExpanded`,
   `coveredHeadings` (re-resolves each phrase against its live writing body, in
   deck order — this list IS the pitch's direction), `pitchRobustness`,
   `findPitchForWriting`, `listOffPitchWritings`. Active selection: when
   `activeId` is null/stale, `pickDefaultActiveId` chooses the most robust pitch,
   ties broken by earliest `createdAt`. Every mutation calls `save()` (persists +
   `window.tinkerSync.pushPitches()`) and fires `tinker:pitches-changed`.
   Boot/hydrate only `reloadFromStorage`; alias `window.tinkerAltPitches` to the
   same object for back-compat.
   **CHECKPOINT — stop and report.** Seed `tinker.tree.v1`, reload, confirm the
   migration wraps it as `pitches[0]`, `getActivePitchId` returns that pitch,
   `coveredHeadings` lists only headings whose phrase still resolves in the live
   body, and `getPitches()[].displayName` falls back personal → ai → `Untitled`.

3. **Wire the debounced organize trigger + server job.** Client:
   `scheduleOrganize` (debounce `ORGANIZE_DEBOUNCE_MS`) on `tinker:writing-saved`
   and `tinker:auth-changed`; `triggerOrganizeNow({ force })` cancels the
   debounce, short-circuits on an unchanged `organizeHash` unless forced, fires
   `tinker:organize-started`, POSTs `/api/pitches/organize` with the Stytch JWT,
   folds the returned blob via `applyServerBlob`, diffs `placementSnapshot`
   before/after, and fires `tinker:organize-completed` with `{ ok, diff }`.
   Server: `api/pitches/organize.js` authenticates via `authenticateSession`,
   loads kinds `essays`/`drafts`/`pitches` from `TinkerUserData`, calls
   `organize` from `api/_lib/pitches-organizer.js` with `clusterWritings` /
   `nameWritings` from `api/_lib/pitches-clusterer.js` as the cluster/name
   dependencies, saves kind `pitches`, returns `{ ok, pitches, updatedAt,
   summary }`. Keep `api/alt-pitches/index.js` (`mode: "cluster"` / `"name"`)
   live as the legacy client-orchestrated path against the same helpers.

4. **Build the classifier (`api/classify/index.js`).** `POST /api/classify`,
   Bearer Stytch token, body `{ writingId, body }`. Build the system prompt from
   `DECK_HEADINGS` + `HEADING_DESCRIPTIONS` (each heading's description lifted
   from `pitch-deck.md`). The model returns a single JSON object
   `{ deckHeading, phraseText }`; `deckHeading` is one of the eleven literals or
   null, `phraseText` is a verbatim 3–18-word substring or null. Validate the
   heading against the const; resolve `phraseText` → `{ offset, length }` with
   `resolvePhraseText` (exact `indexOf`, then a whitespace-normalized fallback,
   with word-boundary checks). Retry once on a malformed reply, then drop the bad
   field — never invent a heading or a phrase. Return `{ deckHeading: string |
   null, phrase: { writingId, offset, length } | null }`. Model:
   `claude-haiku-4-5-20251001`, key held server-side via `ANTHROPIC_API_KEY`,
   system prompt cached (`cache_control: ephemeral`).
   **CHECKPOINT — stop and report.** POST a real draft body. Confirm the reply's
   `deckHeading` is one of the eleven exact strings (or null), the resolved
   `phrase` offsets re-slice to a clean verbatim substring of the body, a
   malformed `phraseText` triggers exactly one retry then drops to null, and no
   free-form text leaks into the response.

5. **Build the publish path.** Client: `publishPitch(pitchId)` resolves the
   pitch's deck into `{ [heading]: ["verbatim", ...] }` via `resolveDeckPhrases`
   (re-slicing each phrase record against its live writing body and collapsing
   whitespace), requires a non-empty display title and at least one resolved
   phrase, POSTs `/api/publish/pitch` with the Stytch JWT, fires
   `tinker:pitch-published`, returns `{ ok, slug, readerUrl, beatCount,
   updatedAt }`. Server: `api/publish/pitch.js` validates `{ title, slides }`
   (title ≤ `MAX_TITLE_LEN` 24 chars, one phrase per heading, phrases ≤
   `MAX_PHRASE_LEN`), derives the slug with `slugify` (lowercase ASCII, non-alnum
   → single hyphen, trimmed), calls `renderDeck` from `api/_lib/deck-template.js`,
   upserts `TinkerUserData` under kind `published:<slug>` with `{ title, slug,
   markdown, beatCount, generatedAt }`, and returns `{ ok, slug, beatCount,
   updatedAt, readerUrl }` (reader host resolved by `readerHost` — prod
   `https://beginner.work`, preview the beginner main alias). `renderDeck` keeps
   `pitch-deck.md`'s Marp frontmatter, renders a cover + one beat slide per
   non-empty heading (post-format paragraphs, the `beginner` badge svg) + a
   closer. The slug + `readerUrl` are what `build-prompts/pitch-review-reveal.md`
   and `build-prompts/social-feed.md` consume — do not render those screens here.

6. **Build the pitch script view (`src/renderer/pitch-script.js`).** Implement
   `getPitchScript(pitchId)` in `pitches.js`: resolve the deck phrases, drop
   headings with no resolved phrases, and compute a per-slide `seconds` from word
   count at ~130 wpm (rounded to the nearest 5, floored at 10, capped at 60);
   return `{ title, slides: [{ heading, phrases, seconds }] }`. The view renders
   into `<section id="pitch-script">` via `window.tinkerPitchScript.show(pitchId)`
   (reached through `window.tinkerShowPitchScript(pitchId)` in `renderer.js`):
   a `Back` button (returns to the feed via `window.tinkerShowPitch`), the
   surface title `Prepare a script for a video`, the pitch title, a `Total`
   duration (`formatDuration`), one `SLIDE n` block per slide with its heading,
   `~<duration>`, and verbatim phrases, plus a `Copy script` button that writes
   `scriptToPlainText(script)` to the clipboard and flips to `Copied` for 1.5s.
   When the pitch has no resolved phrases, show the `emptyHint`. Phrase / heading
   / pitch-title nodes carry `data-audit-ignore` because they're founder content,
   not chrome strings.
   **CHECKPOINT — stop and report.** Open the script for a pitch with several
   covered headings. Confirm the slides match its `coveredHeadings`, the
   durations are 5-second multiples in 10–60s, `Total` sums them, `Copy script`
   produces the same top-to-bottom plain text, and a pitch with zero resolved
   phrases shows `emptyHint` instead of an empty storyboard.

## Constraints (non-negotiable)

- **The eleven `DECK_HEADINGS` are the contract.** Renderer const, classifier
  return values, cluster headings, publish validator, and `renderDeck` all
  reference the same fixed list in the same order, spelled exactly as in
  `pitch-deck.md` (`Why Now?` with its `?`, `How We Make Money` in Title Case).
  No alternate spellings, no case-insensitive matching.
- **Phrases are verbatim.** Every phrase traces to `{ writingId, offset,
  length }` and is re-resolved against the live body before it's shown or
  published. The classifier returns `{ deckHeading, phraseText }` (verbatim 3–18
  words); `resolvePhraseText` grounds it. No smoothing, no truncation past the
  founder's own words.
- **One phrase per heading.** `MAX_PHRASES_PER_HEADING === 1` everywhere; a newer
  phrase replaces the older one for that heading.
- **Model is `claude-haiku-4-5-20251001`.** Both `api/classify/index.js` and
  `api/_lib/pitches-clusterer.js` use it. Never write `claude-sonnet-4-6` — it
  does not exist in this repo.
- **AI classifies, clusters, and names — it never authors.** Every Claude call
  returns structured data or verbatim substrings; titles validate to a single
  word (`validateTitle`), headings to the eleven literals, phrases to grounded
  offsets. Validate the response shape and reject anything outside it.
- **Server-driven organize; debounced trigger; idempotent job.** Boot/hydrate
  never run the AI. The client fires one debounced POST after writings change;
  the server does the cluster + name work and persists the authoritative blob.
- **Auth + key server-side.** Every endpoint authenticates the Stytch session
  with `authenticateSession`; `ANTHROPIC_API_KEY` is read only server-side.
- **Script is not publish.** `pitch-script.js` builds a storyboard; it ships
  nothing. Publishing is `publishPitch` → `/api/publish/pitch` only.
- **Hand off, don't duplicate.** The post-publish arrangement/reveal screen and
  the social feed live in `build-prompts/pitch-review-reveal.md` and
  `build-prompts/social-feed.md`. This build ends at the diff and the slug.
- **Design system compliance.** All surfaces follow
  `build-prompts/design-system.md`: Fraunces display + Instrument Sans body,
  the token scale, no motion in the product layer, shadows on buttons only, no
  pure white / no harsh black in the paper layer, no emoji or exclamation points.

## Done when

- `tinker.pitches.v1` holds the multi-pitch blob; a returning user on
  `tinker.tree.v1` is migrated silently into `pitches[0]` with
  `_migratedFromTree: true`.
- `window.tinkerPitches` exposes `getPitch`, `getPitches`, `findPitchForWriting`,
  `coveredHeadings`, `setActivePitch`, `getActivePitch`, `getActivePitchId` (plus
  the mutation + organize + publish surface); the active pitch defaults to the
  most robust one.
- A writing save fires a single debounced `/api/pitches/organize` POST; the
  server clusters and names off-pitch writings and returns the authoritative
  blob; the client folds it back and re-renders. `api/alt-pitches/index.js`
  remains live for the legacy round-trip.
- `/api/classify` returns `{ deckHeading, phrase }` for a writing — one of the
  eleven literals (or null) plus a grounded verbatim phrase (or null), via
  `claude-haiku-4-5-20251001`, with one retry and no invented copy.
- `publishPitch` → `/api/publish/pitch` renders the pitch into a Marp
  daily-beginner post via `renderDeck`, stores it under kind `published:<slug>`,
  and returns the slug + `readerUrl` for the review-reveal and feed surfaces.
- `window.tinkerShowPitchScript(pitchId)` opens `<section id="pitch-script">`
  with the storyboard: per-slide headings, ~130-wpm durations, verbatim phrases,
  `Total`, and a working `Copy script`. An empty pitch shows `emptyHint`.
- Every visible phrase / storyboard line / published beat is a verbatim
  substring of the founder's writing; no AI-authored copy appears anywhere; the
  Anthropic key is never in a browser request.
