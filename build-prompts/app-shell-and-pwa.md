# Build the tinker app shell + PWA chrome

> Version: v0.100
> Generated by the founder-package skill (product spec flow).
> Reconstructed from shipped code by the build-prompts audit (2026-05).

Build the chrome that hosts every other surface in tinker: the HTML shell, the
view router, the mobile drawer, the iOS install hint, the cross-install session
bridge, and the share / update affordances. This is the load-bearing
infrastructure — the founders feed, the writing flow, the pitch script, and the
category feed all mount into `<section>`s defined here and switch through the
one router in `renderer.js`. The shell ships as plain web / PWA and is reused
verbatim by the Electron desktop and Capacitor mobile shells (README → "How the
platforms differ"); none of the files below are platform-specific, but several
detect the runtime and step out of the way.

## Anti-patterns — do not repeat

- **Don't introduce a framework, bundler, or build step.** This is plain
  HTML/CSS/JS loaded with `<script defer>` tags in a fixed order. README says it
  twice: *"no build step, no bundler."* `vercel.json` serves `src/renderer`
  directly as `outputDirectory`. Adding React/Vite/webpack breaks the Electron
  and Capacitor shells, which point straight at `src/renderer/`.
- **Don't reorder the `<head>` script tags casually.** Load order is contractual:
  `pwa-session.js` must run before `auth.js` (it imports the JWT off the launch
  URL before auth reads it); `sync.js` runs before `seeds.js` / `heatmap.js` /
  `sidebar-tree.js` so its `hydrate()` can fire before they first render;
  `pitches.js` loads before `sidebar-tree.js`. Read the inline comments in
  `index.html` — they document each ordering reason.
- **Don't build a real multi-page app or a client router with URL paths.** Every
  view is a `<section>` inside `<main class="stage">`; switching views toggles
  the `hidden` attribute and the welcome section's `data-active`. There is no
  History API routing for views (only `pwa-session.js`'s one `replaceState` to
  scrub the `#ts=` token off the launch URL). Do not add `/writing`,
  `/founders`, etc.
- **Don't add an address bar.** The README "Shortcuts" table and renderer
  comments mention a Cmd/Ctrl+L "focus address bar" idea, but the live renderer
  has no address bar — the shortcut handler is gone and a comment marks it
  `[NEEDS INPUT]`. tinker is a writing tool, not a browser tab. Do not ship one.
- **Don't show the install banner, share button, or update banner in the wrong
  runtime.** Each affordance gates on runtime: the share button reveals only when
  standalone or wrapped; the iOS install hint shows only on iOS Safari/Chrome,
  not standalone, not Capacitor/Electron, not in-app webviews; the update banner
  skips wrapped runtimes (their updates ship through the App Store / auto-updater).
  Respect every guard.
- **Don't design new chrome per surface.** Sections inherit `styles.css`,
  `design-tokens.css`, the rainbow-web globe mark, and the type stack
  (Fraunces / Instrument Sans for the product layer; Plus Jakarta / Inter still
  loaded for legacy chrome). The shell is the design; sections fill it.

## Read first

- `src/renderer/index.html` — the shell itself. Every `<section>`, the sidebar,
  the auth gate markup, the PWA install banner + sheet, and the ordered
  `<script defer>` manifest. The seven stage sections are: `welcome`, `writing`,
  `read`, `writing-fit`, `founders`, `pitch-script`, `category-feed`.
- `src/renderer/renderer.js` — the view router. The `show*` functions
  (`showFeed`, `showWriting`, `showRead`, `showCategoryFeed`, `showWritingFit`,
  `showFounders`, `showPitchScript`) each reveal one section and hide the rest.
  Owns `window.tinkerStore`, the welcome-grid handlers, the read-view action
  menu, the status composer, and the `tinker:hydrated` re-render. Exposes
  `window.tinkerShowPitchScript(pitchId)`, `window.tinkerShowPitch()`,
  `window.tinkerNewSession(preset)`, `window.tinkerOpenEssay(id)`,
  `window.tinkerResumeDraft(id)`, `window.tinkerShowCategoryFeed(key, seed)`.
- `src/renderer/platform-mobile.js` — the runtime shim. Adds `on-web` or
  `on-capacitor` to `<html>`, polyfills `window.tinker.*` (`callClaude`,
  `openExternal`, `platform()`, settings), and proxies every Claude call through
  `/api/claude/converse` with the `tinker_jwt` Bearer token. Short-circuits when
  Electron's preload already installed `window.tinker`.
- `src/renderer/pwa-session.js` — carries the sign-in across the iOS PWA install.
  `importTokenFromHash()` reads `?#ts=<jwt>` off the launch URL into
  `localStorage.tinker_jwt` and scrubs the URL; `injectSessionIntoManifest()`
  rewrites `start_url` to `/#ts=<jwt>` in a `data:` manifest so "Add to Home
  Screen" carries the session. (Also referenced by the auth spec — same file.)
- `src/renderer/mobile-drawer.js` + `mobile-drawer.css` — the hamburger drawer
  under 540px. Toggles `body[data-drawer-open]`; inert on wider viewports.
- `src/renderer/pwa-install-hint.js` + `pwa-install-hint.css` — the iOS install
  banner (`#pwa-hint`) and the share-sheet instructions bottom-sheet
  (`#pwa-hint-sheet`), with Safari vs. Chrome-iOS step variants and a
  drag-to-close gesture.
- `src/renderer/share.js` — the sidebar `#nav-share` button. `navigator.share()`
  with a clipboard fallback; revealed only standalone / wrapped.
- `src/renderer/update-banner.js` — polls `/api/version`; when a newer deploy
  appears, re-skins `#pwa-hint` into "Update" mode (reload on tap). Skips wrapped
  runtimes.
- `src/renderer/icon-init.js` — renders the globe mark to a PNG via `<canvas>`
  and hands it to `window.tinker.setIcon` so the Electron dock/taskbar shows the
  brand icon. No-op when `setIcon` isn't present (web/Capacitor).
- `src/renderer/manifest.json` — the static PWA manifest (`start_url: "/"`,
  standalone, `#F5F3EF` theme). `pwa-session.js` personalises a copy at runtime.
- `src/renderer/auth.js`, `src/renderer/sync.js` — the gate and the data layer
  that mount into this shell (their own build prompts: `auth-phone-pin.md`,
  `data-sync.md`). The shell only needs to host their markup and load them in
  order.
- `README.md`, `package.json`, `vercel.json`, `capacitor.config.json` — the run
  targets (`npx vercel dev`, `npm run web`, Electron `npm start`, `npx cap sync`)
  and the no-build-step contract.

## What you're building, in one paragraph

A single `index.html` shell with a fixed sidebar (`<aside class="sidebar">` —
brand button, the pitch-deck tree mount, an Account section with Receipts and a
runtime-gated Share button, footer) and a `<main class="stage">` holding seven
hidden `<section>`s, exactly one of which is visible at a time. `renderer.js` is
the only router: a family of `show*` functions that flip `hidden` /
`data-active` and call into the owning module (`window.tinkerWriting.open`,
`window.tinkerFounders.refresh`, `window.tinkerPitchScript.show`,
`window.tinkerHeatmap.getCategoryFeed`) to populate the revealed section. The
welcome section is the default landing (a 2×2 place grid — Cafe / Home / Work /
Somewhere else — that seeds a writing session). Around the stage sit four
cross-cutting chrome modules that each detect the runtime and gate themselves:
the mobile drawer (under 540px), the iOS install hint (iOS browser only), the
share button (standalone/wrapped only), and the update banner (web/PWA only).
Two more modules bridge platform concerns: `platform-mobile.js` (the
`window.tinker.*` polyfill + Claude proxy) runs first, and `pwa-session.js`
smuggles the JWT through the iOS install boundary. `icon-init.js` brands the
Electron dock. No bundler, no build step, no client-side path router.

## Build sequence

1. **The shell document.** Write `src/renderer/index.html`: the `<head>` (CSP
   meta, `noindex` robots meta, font preconnect + Google Fonts link for
   Fraunces / Instrument Sans / Plus Jakarta / Inter, the four stylesheet links
   `styles.css` / `design-tokens.css` / `mobile-drawer.css` /
   `pwa-install-hint.css`, the manifest link, the PWA meta tags and theme-color
   `#F5F3EF`), then the **ordered head scripts**: `pwa-session.js`, `sync.js`,
   `transactions.js`, `seeds.js`, `heatmap.js`, `pitches.js`, `sidebar-tree.js`
   — each `defer`, each with the inline comment explaining its ordering reason.
   Then the `<body>`: the liquid-glass SVG filter defs, the `#drawer-toggle`
   hamburger + `#drawer-backdrop`, the `<aside class="sidebar">` (brand
   `#nav-home`, the `nav.sidebar__tree` mount rendered by `sidebar-tree.js`, the
   `nav.sidebar__account` with `#nav-receipts` and the hidden `#nav-share`, the
   footer, `#loadbar`), and the `<main class="stage">` with the **seven
   sections** — `welcome` (default `data-active`), `writing`, `read`,
   `writing-fit`, `founders`, `pitch-script`, `category-feed` — each carrying the
   inline comment that documents what mounts there. Close with the auth gate
   markup (`#auth-gate`), the PWA install banner + sheet (`#pwa-hint`,
   `#pwa-hint-sheet`), and the **ordered body scripts**: `platform-mobile.js`
   first, then `auth.js`, `lib/rainbow-web.js`, `icon-init.js`, `writing.js`,
   `renderer.js`, `founders.js`, `pitch-script.js`, `mobile-drawer.js`,
   `pwa-install-hint.js`, `share.js`, `update-banner.js`.
   **CHECKPOINT — stop and report.** Serve via `npx vercel dev` (or `npm run web`
   for static-only). Confirm the welcome section renders, the four place tiles
   show, the sidebar brand + Account section show, and no console errors fire
   from a missing script or out-of-order load.

2. **The runtime shim — `platform-mobile.js`.** Build it to run before anything
   that calls Claude. It returns early if Electron's preload already set
   `window.tinker.callClaude`; otherwise it adds `on-web` (or `on-capacitor`) to
   `<html>` and installs `window.tinker` with `callClaude({ system, messages,
   model, maxTokens })` that POSTs `/api/claude/converse` with the `tinker_jwt`
   Bearer token, plus `openExternal`, `platform()`, `setIcon` (no-op),
   `setSetting`/`getSetting`. On a 401 it clears `tinker_jwt` and calls
   `window.tinkerAuth.showGate()` rather than reloading. The browser never holds
   an Anthropic key — the proxy does. (This is the seam the auth and data-sync
   specs depend on; keep `tinker_jwt` as the one token key.)

3. **The view router — `renderer.js`.** Build the `show*` family. Each one
   removes/sets `welcome`'s `data-active`, sets `hidden` on the other six
   sections, resets `activeId` / `readingEssayId` / `activeCategoryKey`, calls
   `renderSidebar()`, and then hands off to the owning module. Wire `#nav-home`
   to `showFeed`; the welcome grid (`data-location` tiles → `startSessionWith`,
   with "other" revealing `#welcome-form`); the read-view action menu
   (`#read-menu-trigger` → archive/delete on `window.tinkerStore`); the status
   composer; the Cmd/Ctrl+T (new draft) and Cmd/Ctrl+W (delete active draft)
   shortcuts; and the `tinker:hydrated` listener that re-reads drafts/essays from
   localStorage and re-renders without bouncing an open writing/read view.
   Expose the public router APIs on `window`: `tinkerShowPitch`,
   `tinkerShowPitchScript`, `tinkerNewSession`, `tinkerOpenEssay`,
   `tinkerResumeDraft`, `tinkerShowCategoryFeed`, and the writing callbacks
   `tinkerOnWritingClose` / `tinkerOnWritingPublish` / `tinkerOnDraftChange`.
   Boot by calling `showFeed()`.
   **CHECKPOINT — stop and report.** Confirm: tapping a place tile opens the
   writing section; closing returns to welcome; opening an essay shows the read
   section with its action menu; the founders / pitch-script / category-feed
   sections each reveal correctly when their entry point fires; only one section
   is ever visible.

4. **The mobile drawer.** Build `mobile-drawer.js` + `mobile-drawer.css`: under
   540px the sidebar slides over the stage; `#drawer-toggle` toggles
   `body[data-drawer-open]`, the backdrop / Escape / a resize past the breakpoint
   close it, and tapping a tree phrase row or the brand auto-closes it. Inert at
   ≥541px. Keep styling/transitions in the CSS; keep the toggle logic in the JS.

5. **The iOS install hint + cross-install session bridge.** Build
   `pwa-install-hint.js` + `pwa-install-hint.css` and `pwa-session.js` together
   (they cooperate across the AHTS boundary). The hint shows `#pwa-hint` only on
   an iOS WebKit Safari/Chrome browser that is not standalone, not wrapped, not
   an in-app webview, and not previously dismissed (`tinker_pwa_hint_dismissed`);
   tapping Install opens `#pwa-hint-sheet` with the correct step variant
   (default vs. `--chrome`) and a drag-to-close gesture. `pwa-session.js` imports
   `?#ts=<jwt>` into `localStorage.tinker_jwt` on every load (before `auth.js`
   reads it) and, once signed in, rewrites the manifest's `start_url` to
   `/#ts=<jwt>` via a `data:` URL so installing carries the session. Both no-op
   in wrapped runtimes and degrade gracefully when localStorage/manifest fetch
   fail.
   **CHECKPOINT — stop and report.** In an iOS Safari simulator (or with the UA
   spoofed), confirm the banner appears after the gate drops, the sheet shows the
   share-sheet steps, and dragging it down dismisses it. Confirm the manifest
   `<link>` href becomes a `data:` URL once a token exists.

6. **Share, update, and icon chrome.** Build `share.js` (reveal `#nav-share`
   only when standalone/wrapped; `navigator.share()` → clipboard fallback with a
   "Copied" flash), `update-banner.js` (poll `/api/version` every 60s, re-skin
   `#pwa-hint` into Update mode on a new deploy, reload on tap, per-version
   dismiss; skip wrapped runtimes), and `icon-init.js` (canvas-render the globe
   to PNG, hand to `window.tinker.setIcon`; no-op without it). These are the
   last body scripts and depend only on the shell DOM already being present.

## Constraints (non-negotiable)

- **No build step, no bundler, no framework.** Plain `<script defer>` files
  served straight from `src/renderer/`. `vercel.json` `outputDirectory` is
  `src/renderer`; Capacitor's `webDir` and Electron both point at the same
  directory. A build tool breaks all three shells.
- **Preserve the script load order.** `pwa-session.js` before `auth.js`;
  `sync.js` before the consumer modules; `pitches.js` before `sidebar-tree.js`;
  `platform-mobile.js` first in the body. The inline `index.html` comments are
  the spec for why.
- **One section visible at a time.** All view switching goes through
  `renderer.js`'s `show*` functions via the `hidden` attribute and welcome's
  `data-active`. No new client path router, no History API view routing.
- **The seven sections are fixed.** `welcome`, `writing`, `read`, `writing-fit`,
  `founders`, `pitch-script`, `category-feed`. New surfaces mount as siblings and
  get their own `show*` function; do not repurpose an existing section's id.
- **One token key everywhere: `tinker_jwt`.** The shim, `pwa-session.js`,
  `sync.js`, and `auth.js` all read/write the same localStorage key. The proxy
  sends it as a Bearer token to `/api/claude/converse`.
- **Runtime gating is mandatory.** Share button: standalone/wrapped only.
  Install hint: iOS Safari/Chrome, not standalone/wrapped/webview, not
  dismissed. Update banner + icon-init: web/PWA paths only (skip wrapped /
  no-`setIcon`). Never show an affordance in a runtime where the OS already
  covers it.
- **Inherit the design system.** `styles.css`, `design-tokens.css`, the rainbow
  globe mark, the loaded font stack. The shell adds no new visual language.
- **Keep CSP and `noindex` intact.** The `<head>` ships a strict
  Content-Security-Policy meta and `noindex, nofollow` (belt-and-suspenders with
  the `X-Robots-Tag` header in `vercel.json`). The private-beta surface stays out
  of search.

## Done when

- `npx vercel dev` serves the shell; the welcome section is the default landing
  and the sidebar (brand, tree mount, Account) renders.
- Tapping a place tile opens the writing section; closing returns to welcome;
  publishing routes to `writing-fit`; opening an essay shows `read`; the
  founders, pitch-script, and category-feed sections each reveal through their
  `show*` entry point — with exactly one section visible at any time.
- Under 540px the hamburger opens the drawer; backdrop / Escape / resize close
  it; the drawer is inert above the breakpoint.
- On a (spoofed) iOS browser, the install banner appears after the auth gate
  drops, the sheet shows the right step variant, and the manifest link becomes a
  personalised `data:` URL once a token exists.
- The share button is hidden in a plain tab and revealed when standalone; the
  update banner re-skins `#pwa-hint` when `/api/version` reports a newer deploy;
  neither fires inside Capacitor/Electron.
- No bundler or build step was introduced; the same `src/renderer/` directory
  still loads under Electron (`npm start`) and Capacitor (`npx cap sync`) without
  modification.
