Build prompt v3:

````markdown
# tinker — v1 Build Prompt

You are an engineering agent. Build the first version of **tinker** — a
guided essay writer where the maker answers questions and Claude stitches
the answers into a published essay — inside the existing tinker repo at the
current working directory.

**Proceed without asking any questions.** Where the spec is silent, make the
smallest, most reversible choice and write it (one line, with rationale) to
`BUILD-NOTES.md` so the maker can correct it after seeing the build run.

## Read first
1. `product-spec.md` — the spec. Treat it as the constraint.
2. `pitch-deck.md` — context for *why*. Background only.
3. The current `src/` tree. Many earlier assumptions (rainbow-web tokens,
   import surface, trajectory page, hero block, fixture posts, voice
   surface) are NO LONGER in scope. If they exist, remove them.

## What v1 is
The maker — and only the maker — opens tinker in dev mode and writes an
essay by answering Claude's adaptive questions. Each answer is stitched into
a growing essay; the maker approves each edit inline. When done, the maker
picks a handle and a contact link and publishes. The essay appears at
`/[handle]` and on a public feed of all published essays. The writing UI is
disabled in production for everyone.

There is no audience-specific framing surfaced in the UI. Claude filters
internally for what would land with seed investors, but the maker just sees
a question and an essay. There is no voice mimicry, no titles, no
likes/comments/saves, no name, no photo, no bio. Text-first, minimal.

## What v1 ships

### Surface 1 — Homepage (public)
- 240px left sidebar.
  - In production: tinker wordmark only.
  - In dev: maker's drafts (labeled by the first question Claude asked in
    that session) and maker's published essays (labeled by `/handle · date`).
- Main column: HN-style numbered feed of all published essays.
  - Each row: `1. /tyler-lindow · 2026-05-05 · first ~80 chars of essay
    body…` — entire row clickable.
  - Sort: most-read essays float up; recency weighted (click on a row from
    the feed counts as a read).
  - Top of feed: "Write yours" CTA. Disabled in production with caption
    "Private beta." Enabled in dev to open Surface 2.

### Surface 2 — Writing UI (dev-only)
- Three zones, fixed positions:
  - **Top (pinned):** the current question Claude is asking, single line,
    monospace.
  - **Middle (scrollable):** the essay as it grows. Pending stitching edits
    appear inline with a coral-tinted highlight and Accept/Reject controls
    beside them.
  - **Bottom (fixed):** input textarea + Send button.
- First question of every new draft is hardcoded: **"What's the most
  interesting thing you learned recently?"**
- Subsequent questions: Claude generates from the conversation so far.
- Loop:
  1. Maker types an answer; clicks Send.
  2. Claude proposes a stitching edit (inserted into the essay) shown
     highlighted in the middle zone.
  3. Maker clicks Accept (edit becomes essay text) or Reject (edit
     discarded; Claude proposes another).
  4. Once resolved, Claude generates the next question and pins it on top.
- Variable length. Two end-of-session buttons: "Save draft" (returns to
  homepage; draft in sidebar) and "Publish" (opens Surface 3).
- Drafts auto-save to localStorage on every accept/reject.

### Surface 3 — Publish form
- Two text inputs only:
  - **Handle** (URL slug; must be unique against existing published essays).
  - **Contact link** (email or URL; free text).
- One primary button: "Publish."
- On submit: append to the published essays store, redirect to `/[handle]`,
  new essay appears at top of feed (zero reads, ranks by recency).

### Surface 4 — Reader page (`/[handle]`)
- Header: `/handle · 2026-05-05` in monospace, muted.
- Body: essay as prose. Body sans, 18px, 1.6 line-height, max-width ~680px,
  centered.
- Footer: one line — `Reach me at: [contact] · Share`. "Share" copies the
  page URL to clipboard.
- Nothing else.

## Visual canon — claude.ai/code, light only

Single canon across all surfaces. No dark mode in v1.

- **Background:** `#fafafa` (warm off-white).
- **Text:** `#1a1a1a` (near-black, warm).
- **Accent (coral):** `#cc785c`. Used for active/focused states, primary
  buttons, links, highlight on pending stitching edits.
- **Muted:** `#888`.
- **Hairlines:** `#e5e5e0`.
- **Type:**
  - Body and UI: `-apple-system, BlinkMacSystemFont, "Inter", sans-serif`.
  - Code-feeling accents (handles, dates, sidebar items, question header,
    feed rows): `ui-monospace, "SF Mono", "Menlo", monospace`.
- **Chrome:** generous whitespace. Hairlines only. 6–8px border-radius. No
  shadows.
- **Pending edit highlight:** `background: rgba(204, 120, 92, 0.12)` with a
  1px coral left border.
- **Buttons:** primary = coral bg + white text; secondary = transparent +
  coral border + coral text. Square-ish, no gradients, monospace.

## The line — visible-string allowlist

Every visible string must be one of:
- **(a)** maker's verbatim input, OR
- **(b)** Claude's stitching output the maker accepted, OR
- **(c)** maker's publish-form input (handle, contact), OR
- **(d)** a fixed UI string from this allowlist:

```
Homepage:    "tinker", "Write yours", "Private beta"
Sidebar:     "Drafts", "Published"
Writing UI:  "What's the most interesting thing you learned recently?",
             "Send", "Accept", "Reject", "Save draft", "Publish"
Publish:     "Handle", "Contact link", "Publish"
Reader:      "Reach me at:", "Share"
```

Anything outside (a)–(d) on a public-facing surface is a bug. Add
`scripts/check-strings.ts` that walks rendered output and verifies.

## Storage
- **Drafts:** localStorage on the maker's machine. Each draft: `{id,
  first_question, conversation, essay_paragraphs, created_at, updated_at}`.
- **Published essays:** `data/essays.json` in the repo. Each: `{handle,
  contact, essay, published_at, read_count}`. Production site reads from
  this file. Publishing in dev appends to it; maker commits and deploys.
- **Read counts:** in dev, increment in-memory. In production, a tiny POST
  endpoint updates the JSON file (or, smallest option: read counts are
  computed at deploy-time from server logs and updated weekly — note in
  BUILD-NOTES which approach was chosen).

## Dev-vs-production gating
- Env var `TINKER_MODE=dev` enables the writing UI.
- In production (var unset):
  - "Write yours" rendered but disabled, caption "Private beta."
  - `/write` redirects to homepage.
  - Writing API endpoint returns 403.
- Read-side surfaces work identically in both modes.

## The model
Use `claude-sonnet-4-6` for both question generation and essay stitching.
Two distinct system prompts, both with prompt caching (`cache_control:
{"type": "ephemeral"}`).

### Question system prompt
```
You are tinker's question-asker. Ask the maker one short, specific, curious
question at a time. Each question must build on prior answers, surface
concrete specifics, and pull out details a seed investor would find
compelling — without ever mentioning investors or fundraising. Output
ONLY the question. No preamble, no explanation, no quotes.
```

User message: full conversation so far + current essay state.

### Stitching system prompt
```
You are tinker's editor. Given the maker's latest answer and the essay so
far, propose a stitching edit: one or more sentences to add to the essay.

Rules:
- Use only the maker's words, facts, and claims. Do not invent.
- You may rephrase for prose flow, add brief connectives ("Then," "But,"),
  and reorder for readability.
- Filter for what would land with a seed investor; drop the parts of the
  answer that are not signal-bearing.

Output JSON: {"insertion_point": "append" | <paragraph_index>, "text":
"<new prose>", "replaced_text": null | "<existing text being replaced>"}.
```

User message: maker's latest answer + essay so far (paragraphs indexed).

## Definition of done
1. `npm run dev` opens the homepage; feed visible (empty initially); sidebar
   shows drafts + published (empty).
2. Clicking "Write yours" in dev opens the three-zone writing UI with the
   hardcoded first question pinned.
3. Typing an answer + Send: Claude proposes a stitching edit
   inline-highlighted; Accept commits it; Reject yields another proposal.
4. After the edit, Claude generates the next question and pins it.
5. "Save draft" returns to homepage; draft appears in sidebar labeled by its
   first question.
6. "Publish" opens the publish form; submitting writes to
   `data/essays.json`; new essay live at `/[handle]` and at the top of the
   feed.
7. Reader page renders: `/handle · date`, essay body, "Reach me at:
   [contact] · Share."
8. Unset `TINKER_MODE`: "Write yours" disabled with "Private beta," `/write`
   redirects home, writing API returns 403, feed + reader pages still work.
9. Visual canon consistent across all four surfaces.
10. `scripts/check-strings.ts` passes — no string outside (a)–(d) on any
    rendered surface.

## Out of scope for v1
- Multi-user accounts, auth, sign-in.
- Any kind of import (LinkedIn, Instagram, blog, etc.).
- Voice/audio input.
- Likes, comments, saves, follows, notifications, RSS.
- Names, photos, bios at publish-time.
- Titles on essays.
- Email send, newsletter distribution.
- Markdown / rich text / images / embeds in the essay body.
- Mobile-first design (desktop-first; basic responsive ok).
- Dark mode.
- Search.
- Edit-after-publish.

When v1 is shippable, commit and push to `claude/product-spec-skill-DJC3W`.
**Do not ask for confirmation; proceed.**
````
