# Build the tinker sidebar revamp

> Version: v0.102
> Generated by the product-spec skill.

Build the v1 of the revamped tinker sidebar from this prompt. The founder has worked through a guided interview that distilled the idea into the structure below; this is the imperative form a build agent executes against.

The revamp turns the existing left sidebar (brand at top, flat seed-card list in the middle, Account block at the bottom) into a **three-tier mirror of the founder's writing life**: the places they write from (Earths), the topics that have started to cluster inside each place (Seeds), and the specific things they're learning inside each topic (Growth vectors). Labels at every tier are verbatim phrases lifted from the founder's own writing — the AI clusters and selects, never paraphrases. The flat seed-card list goes away; the three-tier tree takes its place. The brand block and Account block stay.

This is a one-shot revamp. There is no Phase 2, no Electron-only step, no native mobile work. Ship it all to web/PWA, end to end.

## Vocabulary — read this section first

This revamp triggers a three-way collision on the word **seed**. The collision is real: it lives in the code, the data, and the founder's own speech. Resolving it correctly is the precondition for everything below. The rule is:

| Concept | What it is | Where it lives today | Where it lives after this revamp |
|---|---|---|---|
| **Earth** | A place the founder writes from (e.g. `"home"`, `"cafe"`, `"Kitchen counter"`, `"the back porch at 7am"`). The top tier of the new sidebar. | `tinker.seeds.v1` in localStorage; `draft.seed` and `essay.seed` fields on writings; `parsed.seeds` map in the taxonomy blob; the file `src/renderer/seeds.js`. The welcome grid's `data-location` attribute already routes here. | `tinker.earths.v1` in localStorage; `draft.earth` and `essay.earth`; `parsed.earths` in the taxonomy blob; the file `src/renderer/earths.js`. |
| **Seed** (new meaning) | An AI-derived cluster of growth vectors inside one Earth. 2–5 per Earth. Label is a verbatim phrase from one of the writings in the cluster. | Does not exist. | `tinker.seeds.v1` in localStorage (new meaning, after the Earth rename clears the slot); persisted via `sync.js`. Storage shape: `{ [earthId]: [{ label, sourceWritingId, sourceOffset, sourceLength, growthVectorIds: [...] }, ...] }`. |
| **Growth vector** | A topic-level row in the sidebar, derived from clustering. May map to 1+ underlying writings (drafts/essays). When >1, the row shows a count badge. Label is a verbatim phrase from one of the writings it represents. | Does not exist. | Embedded inside each Seed record above as the `growthVectors` array: `[{ label, sourceWritingId, sourceOffset, sourceLength, writingIds: [...] }, ...]`. |
| **Writing** | An individual draft or essay (the unit the founder actually composes). | `tinker.drafts.v1`, `tinker.essays.v1`. Already tagged with the place via `draft.seed` (renamed to `draft.earth` by this revamp). | Same storage; tag renamed to `.earth`. Drafts and essays themselves keep their names. They are the leaf data that growth vectors point into. |

This means there is a one-time, gated localStorage migration to write: rename the keys, rename the fields on every draft/essay, rename the inner taxonomy map. The pattern already exists — `src/renderer/seeds.js` lines 27–82 shows the exact shape of the previous `location → seed` migration. Mirror that pattern for `seed → earth`, gated on a new flag (`tinker.earths.migration.v1`).

The founder uses these four words consistently. Use them in code, in storage keys, in CSS class names, in commit messages. Do not invent synonyms. **"theme" is dead vocabulary** — it was the v0.100 placeholder for what is now called Seed. Remove every occurrence.

## Anti-patterns — do not repeat

- **Don't invent a new sidebar component alongside the existing `.sidebar`.** This is a refactor in place. The current `<aside class="sidebar" id="sidebar">` in `src/renderer/index.html` stays; the `#home-list` slot is what changes. A second sidebar bolted alongside the first is the failure mode.
- **Don't author labels at any tier.** Every visible label — Earth name, Seed cluster label, Growth vector label — must be a verbatim phrase the founder has actually written or used. Earth labels are the existing place names (`"home"`, `"cafe"`, `"Kitchen counter"` — whatever's already in `tinker.seeds.v1` / soon `tinker.earths.v1`). Seed and Growth vector labels are verbatim substrings of one of the founder's drafts/essays, identified by offset + length, validated at the API layer. A label like `"your career stuff"` or `"thoughts on family"` is a bug; a label like `"the barber shop"` or `"hop tinctures at 7am"` is correct.
- **Don't conflate code-historic `seed` (place) with the new `seed` (cluster).** The migration renames the place field to `earth`; do not skip it, do not leave aliases, do not introduce a compatibility shim that lets both names work. Two entities with the same name is a bug; the migration is the fix.
- **Don't introduce new fonts, new colors, new button visuals, new icon libraries, or a CSS framework.** The visual canon is `src/renderer/styles.css` + `src/renderer/design-tokens.css` + `src/renderer/tokens/rainbow-web.json`. Reuse `.sidebar__account-item`'s sizing / hover / spacing for rows at every tier. Earth rows, Seed rows, and Growth vector rows are visually a family — same line-height, same padding, indented to show depth. If a visual decision isn't already made in those files, stop and ask the founder before inventing.
- **Don't ship judgmental phrasing anywhere.** No characterizations of the user ("you've been thinking a lot about…"), no AI-narrator voice, no "we noticed". The mirror reflects; it does not commentate. This is the founder's single biggest worry — categorization feeling judgmental is the failure that pulls the revamp.
- **Don't shout the numbering, and don't put numbering on Growth vectors.** The `01`, `02`, `03` ordinals on Earths are quiet by design — muted token-defined text, fixed-width slot, no bold, no accent color, no list-style. Seed rows and Growth vector rows are unnumbered (a fourth tier of structure would imply something there isn't). The moment numbers feel like a progress meter, the curriculum mood breaks.
- **Don't translate "curriculum" into productivity-tool affordances.** No progress bars, no read/unread states, no streaks, no completion checkmarks, no "Next up", no "Continue where you left off". The tree is composed for the founder — it doesn't push them through it. If you find yourself reaching for a productivity-tool primitive to make the mood "more obvious", stop and ask the founder.
- **Don't render an Earth that has nothing under it.** If clustering produced zero Seeds for an Earth (too few writings, all hidden, etc.), that Earth is not rendered. Same rule one level down: a Seed with zero growth vectors is not rendered. Empty branches do not exist in the visible tree.
- **Don't show the tree at all in the cold-start empty state.** Until the founder has at least one Earth with at least one Seed under it, the three-tier nav is not rendered. The brand block sits directly above the Account block. No placeholder, no CTA, no "your seeds appear here" text. (Threshold check is server-returned: the function returns `{ earths: [] }` when there's nothing meaningful to cluster, and the renderer hides the nav entirely.)
- **Don't add an archive, a "show more", a "view all" link, infinite scroll, or pagination.** The tree stays short. Five Earths max in practice. 2–5 Seeds per Earth. Growth vectors per Seed are bounded by what clustering surfaces. Old writing lives somewhere else (out of scope for this revamp).
- **Don't ship a visible "Seeds" or "Growth vectors" header.** A `<nav aria-label="Earths">` is fine for accessibility (sr-only). Visible chrome labels for the tiers are not. The founder's words are the content, not chrome.
- **Don't run clustering across users.** Each user's tree is derived only from their own writings. There is no cross-user signal, no shared taxonomy, no public-facing data.
- **Don't include hidden writings in clustering input.** The existing `tinker.seeds.hidden.v1` (to be renamed `tinker.earths.hidden.v1`) is excluded. Any writing whose Earth is hidden is excluded too. Hidden things stay hidden.
- **Don't ship native mobile or Electron in this revamp.** Capacitor / iOS / Android / Electron targets are out of scope. Web/PWA only. If a code path is mobile-only or Electron-only, leave it as-is — do not extend it, do not break it. The new sidebar runs in the browser.

## What you're building, in one paragraph

A founder who has been writing in tinker for a while opens the app. The sidebar shows them the places they've been writing from — Earths — as the top-level rows. Each Earth, when tapped, reveals 2–5 Seeds: short labels lifted verbatim from the writings they did from that Earth. Each Seed, when tapped, reveals its Growth vectors: shorter labels, also verbatim, representing the specific topics inside. A Growth vector that has more than one underlying writing carries a small count badge. Tapping a Growth vector opens the writing (or, if there's more than one underneath, a small list of them). The whole tree is computed by the clustering step on the server, refreshed on every writing-session close, cached locally for instant render, and persisted across devices via the existing sync layer. Visually it lives inside the same `.sidebar` shell that's there today — same warm-cream surface, same brand block on top, same Account block on the bottom — and reads as a personal curriculum the founder is mid-way through, not a tool with controls.

## Mood — how it should feel

The tree is **a curriculum just for you**. Not a list. Not a file tree. Not a feed. When the founder's eye lands on it, the read is: *"someone — quietly — laid this out for me, from my own words, in an order that's mine."* The Earths are sections; the Seeds are units inside those sections; the Growth vectors are the specific things being learned. It should feel composed, not generated.

The single concrete cue that carries this mood:

**Slight numbering on the top tier.** Earth rows carry a small leading marker that gives a sense of sequence (a quiet `01`, `02`, `03` in muted token-defined text, set as a sibling of the label, not a list-style bullet). Seeds and Growth vectors are unnumbered — they're the units and leaves, not the chapters. The numbers are not interactive, not bold, not in an accent color; they read as quiet ordinals, the same way a thoughtful syllabus numbers its sections without shouting.

The number is for *order*, not for *count*. It does not change when the founder adds a new writing; it changes only when clustering produces a new Earth on the tree. The format is part of the visible-string allowlist (see Constraints below).

What this mood is NOT:
- It is not progress tracking. No "3 of 5 read," no progress bars, no checkmarks, no percentages.
- It is not gamification. No streaks, no XP, no achievements.
- It is not an editor's voice. The tree does not narrate, recommend, prioritize, or judge.
- It is not a sidebar nav from a productivity app. No section headers, no group titles, no "Recently used" or "Pinned" affordances.

## The tree, drawn

```
[Earth: home]                              ← row reuses .sidebar__account-item visuals
  [Seed: "the barber shop"]                ← indented one level; same visual family
    [Growth vector: "his hands"]  (3)      ← indented two levels; (3) = count badge
    [Growth vector: "the chair"]
  [Seed: "hop tinctures at 7am"]
    [Growth vector: "what I taste first"]
[Earth: cafe]
  [Seed: "career stuff"]
    [Growth vector: "the thing I'm avoiding"]  (2)
[Earth: Kitchen counter]
  [Seed: "...verbatim phrase..."]
    [Growth vector: "...verbatim phrase..."]
```

- **Earth rows** are always rendered (if the user has at least one Earth with at least one Seed). Tap to expand/collapse the Earth's Seed list. Default state on first paint: the most-recently-used Earth is expanded; the others are collapsed.
- **Seed rows** appear under an expanded Earth. 2–5 per Earth. Tap to expand/collapse the Seed's Growth vector list.
- **Growth vector rows** appear under an expanded Seed. Tap behavior depends on the count badge:
  - No badge (1 underlying writing): tap opens the writing in the stage area to the right (same way tapping a seed card opens a writing today).
  - Badge with `(N)` where N≥2: tap opens a small list — visually a stack of N rows, each reusing `.sidebar__account-item` styling, showing the writing's title — and the founder picks which one to open. The list renders inline below the Growth vector row (sidebar stays the surface; no modal, no stage takeover for the picker).
- **Active state.** Only the currently-open row (Earth, Seed, Growth vector, or individual writing in the multi-essay list) carries the active background. Ancestor rows do not get a path-highlight; the founder asked for subtle, not a breadcrumb trail.
- **Loading state.** While clustering is running after a writing-session close, the existing tree stays rendered and a faint skeleton shimmer overlays the rows being recomputed. No spinner, no "thinking..." text. If clustering fails, the tree silently falls back to its last cached state; a tiny `↻` affordance appears next to the topmost Earth so the founder can retry manually.
- **Hidden writings.** Excluded from clustering input. The existing "Hidden" affordance (whatever pattern `seeds.js` exposes today after the rename) stays available at the bottom of the sidebar, below the Account block or wherever it lives today. Do not move it.

4. **The real clustering step.** Add a new Vercel function — propose `api/cluster/index.js` — that:
   - Accepts the Stytch JWT as Bearer, verifies it against Stytch's JWKS the same way `/api/search` does.
   - Pulls the user's drafts + essays from the request body (or reads them server-side via the existing `/api/user-data/*` surface — pick whichever path is simpler given the existing function signatures). Hidden writings are excluded by the caller before they're sent; the function trusts its input.

For each Earth with ≥3 writings under it, calls Claude Haiku 4.5 to produce 2–5 Seeds, each a `{ label, sourceWritingId, sourceOffset, sourceLength, growthVectors: [...] }`. ## Constraints (non-negotiable)

- **Inside the existing shell.** The `<aside class="sidebar">` in `src/renderer/index.html` stays. The new tree is a `<nav>` inside it, between `.sidebar__top` and `.sidebar__account`. Visual canon: `src/renderer/styles.css`, `src/renderer/design-tokens.css`, `src/renderer/tokens/rainbow-web.json`. No new fonts, no new color tokens, no new button visuals, no new icon library, no CSS framework, no new sidebar component, no new welcome surface, no new modal stack.
- **Labels are verbatim.** Every Seed label, Growth vector label, and writing title rendered in the tree must trace to a substring of a real user-authored string, validated at the API layer via offsets. Invalid offsets get dropped, not shipped. No AI-authored chrome strings inside the tree (other than the `(N)` badge format and the `↻` glyph).
- **Three-tier hierarchy, in this order.** Earth → Seed → Growth vector → (optional inline list of writings under a multi-writing Growth vector). Do not introduce a fourth tier of grouping. Do not flatten to two tiers. Do not invert the order.
- **2–5 Seeds per Earth.** Not 1, not 6+. If the clustering step would produce only 1 Seed for an Earth, that Earth is omitted from the response. If it would produce 6+, the function trims to the top 5 by writing count.
- **Empty branches don't render.** An Earth with no Seeds, or a Seed with no Growth vectors, is not rendered.
- **Cold-start empty is empty.** Below the threshold (no Earth produced any Seeds), the tree `<nav>` is hidden entirely. The brand block sits directly above the Account block.
- **Refresh on every writing close. Cache locally. Persist via sync.** Three independent properties; honor all three. No debouncing, no manual-only mode.
- **Per-user only.** Clustering reads one user's writings and writes one user's tree. No cross-user signal. No shared taxonomy.
- **Web/PWA only.** Electron and native mobile are out of scope. Don't extend Capacitor paths; don't break them either.
- **Anthropic key server-side.** The clustering function holds the key. Browser never sees it. Mirror `/api/search`.
- **Hidden writings excluded from clustering.** The existing hidden set (renamed to `tinker.earths.hidden.v1`) is filtered out before the API call. Hidden things stay hidden.
